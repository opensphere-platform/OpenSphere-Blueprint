## 1. 에이전트의 종류

| 종류 | 소속 | 책임자(사람) | 전형적인 일 |
|---|---|---|---|
| 개인 에이전트 | 사원 1명 | 그 사원 | 메일 정리, 일정 조율, 문서 초안 작성 |
| 부서 에이전트 | 부서·팀 | 단위 관리자(또는 지정 담당자) | 부서 문의 응대, 부서 지식 검색, 정기 보고서 |
| 프로젝트 에이전트 | 프로젝트 | 프로젝트 소유자 | 이슈 정리, 코드 MR 제안, 빌드 결과 요약 |

**공통 원칙:** 모든 에이전트에는 반드시 **책임자인 사람이 1명 이상** 있다. 책임자 없는 에이전트는 동작하지 않는다(§7).

## 2. 신원의 정본과 투영 (O-7)

**권고: Governance 원장이 정본이고, 필요할 때만 다른 곳에 투영한다.**

| 위치 | 역할 | 언제 |
|---|---|---|
| **Governance 원장**(`unit.type=agent`) | **정본**: 종류, 소속 단위, 책임자, 할당 역할, 상태, 기한, 위험 상한 | 항상 |
| SSO 중계자 | 에이전트를 **기계 클라이언트**로 등록한다. 비밀번호 없이 워크로드 신원으로 인증하고 짧은 토큰을 받는다 | 항상 |
| AD | 전용 OU(`OU=Agents`)의 서비스 계정 | **디렉터리 직접 사용 앱(유형 A, 파일 공유·LDAP 메일 등)에 접근하는 할당이 있을 때만** 프로비저닝 어댑터가 만든다 |
| 각 앱(GitLab, 메신저, ERP 등) | 봇·서비스 사용자 | 해당 앱 자격이 할당됐을 때 어댑터가 만든다. 예: GitLab에 MR을 제안하는 프로젝트 에이전트의 봇 계정 |
| 모델 게이트웨이 | 에이전트별 가상 키(소속 단위에 비용 귀속) | 항상(D-29) |

**왜 AD를 정본으로 두지 않는가:**
- 에이전트는 입사·퇴사가 아니라 **단위와 책임자에 따라 생기고 사라진다.** 그 수명주기는 Governance가 관리한다.
- 모든 에이전트를 AD 계정으로 만들면 장기 암호가 생기고, 디렉터리가 사람이 아닌 계정으로 가득 찬다.
- 그렇다고 AD를 전혀 쓰지 않으면 파일 공유처럼 Kerberos·LDAP로만 붙는 앱에 접근할 수 없다. 그래서 **필요할 때만 투영**한다.

## 3. 인증과 토큰

- 에이전트 런타임은 **장기 비밀번호를 갖지 않는다.** 워크로드 신원으로 SSO 중계자에서 짧은 토큰(기본 15분)을 받는다.
- **사람을 대신할 때는 토큰 교환(RFC 8693)**을 쓴다.
  - 입력: 요청자의 토큰(subject) + 에이전트 신원(actor)
  - 출력: 토큰에 `sub=요청자`와 `act=에이전트`가 함께 들어간다
- **모든 실행 기록**에 남기는 것:
  - 에이전트 ID
  - 요청자 또는 상시 위임자(§5)
  - 위임 ID
  - 위임 사슬(§6)
  - 적용된 정의 revision
- AD 투영 계정이 필요한 경우(유형 A 앱)에도 암호를 사람이 다루지 않는다. 어댑터가 회전하고, 사원 영역 비밀 저장소가 보관한다.

## 4. 실제 권한 계산

| 상황 | 실제 권한 |
|---|---|
| 개인 에이전트 + 본인 요청 | 본인 권한 ∩ 에이전트 위험 상한 |
| 부서·프로젝트 에이전트 + 사람 요청 | 에이전트 할당 역할 ∩ 요청자 권한 ∩ 에이전트 위험 상한(D-15) |
| 요청자 없는 자율 실행 | §5 |
| 에이전트가 다른 에이전트를 호출 | §6 |

**에이전트 위험 상한:**
- Governance 정의(policy)로 설정한다. 사람이 그 자리에서 확인해야 하는 행위의 범위를 정한다.
- D-37 원칙에 따라 **관리자 설정 영역**이다. 제품은 다음을 기본 템플릿으로 제공한다.
  - 높은 위험 등급 행위: 외부 발신, 외부 공유, 권한 신청, 결재 요청 제출, 대량 삭제 → **실행 직전에 책임자 또는 요청자가 확인**
  - 보통 이하: 바로 실행 후 기록

**불변:**
- 결재·정의 활성화·Governance 역할 부여·키 조작은 상한과 무관하게 **불가**하다(G-INV-2).
- 에이전트는 자기 할당·상한을 바꾸는 신청을 **제출할 수 없다.** 사람만 할 수 있다.

## 5. 요청자 없는 자율 실행 (O-4)

예약 작업(매일 9시 보고서), 이벤트 반응(새 문의 메일 분류)처럼 **그 순간 요청한 사람이 없는** 실행이다.

**권고: "상시 위임" 방식으로 허용한다.**
- 자율 실행은 **등록한 사람(상시 위임자)**의 위임으로만 존재한다. 위임 기록에는 대상 행위, 범위, 주기, 만료일이 들어간다.
- **실제 권한 = 에이전트 할당 역할 ∩ 상시 위임자의 *현재* 권한 ∩ 자율 실행 위험 상한**이다. 매 실행마다 다시 계산한다.
- 상시 위임자가 퇴사하거나 권한을 잃으면 해당 자율 실행은 **자동으로 정지**한다. 승계는 §7을 따른다.
- 위임에는 **만료일이 반드시 있다.** 최대 기간은 관리자 설정이며 기본 템플릿은 90일이다. 갱신은 사람만 할 수 있다.
- 자율 실행 위험 상한의 기본 템플릿은 "보통 이하만"이다. 높은 위험 행위가 필요하면 **대기 상태로 만들고 사람 확인을 요청**한다. 그대로 실행하지 않는다.

**권고하지 않는 대안:**

| 대안 | 문제 |
|---|---|
| 자율 실행 금지 | 정기 보고와 이벤트 처리가 막혀 AOA 효용이 크게 준다 |
| 에이전트 자체 권한으로 자율 실행 | 책임자가 퇴사해도 계속 돌아간다. 사람의 권한을 넘는 행위가 가능해진다 |

## 6. 에이전트 간 호출과 위임 사슬

예: 개인 에이전트가 부서 에이전트에게 "부서 규정 검색"을 요청한다.

**권고:**
- 사슬 전체의 **교집합 권한**을 적용한다. 예: 요청자 ∩ 개인 에이전트 상한 ∩ 부서 에이전트 할당 ∩ 부서 에이전트 상한.
- 호출 깊이는 **최대 2단계**다(관리자 설정, 기본값 2).
- 사슬 전체를 실행 기록에 남긴다.
- 순환 호출은 거절한다.

## 7. 수명주기

| 사건 | 처리 |
|---|---|
| 생성 | Governance 신청으로 만든다. 개인 에이전트는 본인 신청 + 정책에 따른 자동 승인. 부서·프로젝트 에이전트는 단위 관리자 결재 |
| 할당 변경 | 사람 신청 + 결재. 에이전트는 자기 할당을 신청할 수 없다 |
| 책임자 퇴사·이동 | §10 Q-4 |
| 소속 단위 해체 | 에이전트 정지 → 데이터 보존 정책(D-33)에 따라 처리 → 폐기 |
| 보안 사고 | 책임자, 단위 관리자, Governance 소유자가 **즉시 정지**할 수 있다. 정지는 결재가 필요 없다(권한을 줄이는 방향). Backbone 보안 동결(D-39)은 모든 에이전트의 새 실행도 멈춘다 |
| 정기 재검토 | 사람 할당과 같은 재검토 캠페인에 포함한다(D-37 설정 따름) |

## 8. 에이전트의 데이터

| 데이터 | 소유 | 범위 |
|---|---|---|
| 개인 에이전트의 기억·대화 | 그 사원 | 본인만. 퇴사 시 D-33 보존 정책 |
| 부서·프로젝트 에이전트의 지식·기억 | 그 단위 | 단위 구성원 권한 안에서 |
| 모델 사용량·비용 | 소속 단위 | Governance showback(D-25) |

- 에이전트가 답할 때 쓰는 검색은 **요청자 권한으로 다시 걸러야 한다.** 부서 에이전트의 지식 저장소에 있다고 해서 요청자가 볼 수 있는 것은 아니다.
- 에이전트 기억에 비밀값을 넣지 않는다. 참조만 둔다.

## 9. 사원 영역 제어 입구와의 관계 (D-36)

- 에이전트는 사원 영역 Shell의 같은 계약으로만 기능을 호출한다. 앱 API를 직접 우회 호출하지 않는다.
- Shell은 매 호출마다 다음을 확인한다.
  1. 토큰의 `act` 사슬
  2. Governance 판단부의 결정(§4~§6 계산)
  3. 위험 상한에 따른 사람 확인 필요 여부
- 사람 확인이 필요하면 Shell이 **대기 작업**을 만든다. 책임자나 요청자가 Workspace에서 승인하면 실행한다. 이 승인은 "에이전트 행위 확인"이며 Governance 결재(권한 부여)와는 다르다.

## 10. 결정이 필요한 사항

| ID | 질문 | 권고안 |
|---|---|---|
| Q-1 (O-7) | 에이전트 신원의 정본과 투영 | **Governance 원장이 정본**. SSO에는 기계 클라이언트로 항상 등록. AD 계정은 디렉터리 직접 사용 앱 접근이 할당될 때만 전용 OU에 투영 |

| Q-3 | 에이전트 간 호출 | **허용, 사슬 교집합, 최대 깊이 2**(관리자 설정) |

### 10.1 보스 결정 (2026-11-17) — 네 가지 모두 권고안 채택

| ID | 결정 |
|---|---|
| D-45 (Q-1, O-7) | 에이전트 신원의 정본은 **Governance 원장**이다. SSO에는 비밀번호 없는 기계 클라이언트로 항상 등록한다. AD 계정은 디렉터리를 직접 쓰는 앱에 접근이 할당될 때만 전용 OU에 투영한다 |
| D-46 (Q-2, O-4) | 자율 실행은 **상시 위임으로 허용**한다. 권한 = 에이전트 할당 ∩ 위임자의 현재 권한 ∩ 자율 위험 상한이며, 매 실행마다 다시 계산한다. 위임자가 권한을 잃으면 자동 정지한다. 만료는 필수이고 최대 기간은 관리자 설정(기본 템플릿 90일)이다. 높은 위험 행위는 대기 후 사람 확인 |
| D-47 (Q-3) | 에이전트 간 호출을 허용한다. **사슬 전체 교집합 권한, 최대 깊이 2**(관리자 설정), 사슬 기록, 순환 거절 |
| D-48 (Q-4) | 책임자가 퇴사·이동하면 **즉시 정지 후 단위 관리자에게 승계를 요청**한다. 수락하면 재개하고, 기본 30일 안에 수락이 없으면 폐기 절차(데이터는 D-33) |

위험 상한(§4)과 각 기간·깊이 기준값은 D-37 원칙에 따라 **관리자 설정 영역**이다. 문서의 수치는 기본 템플릿이다.
