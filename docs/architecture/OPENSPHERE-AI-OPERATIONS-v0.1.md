## 1. 결론 요약

원칙은 하나다. **원장이 결정하고, 집행 지점은 원장을 따르며, 콘텐츠는 집행 경로에 남지 않는다.**

업계는 세 일을 서로 다른 자리에 둔다. 토큰 한도와 즉시 차단은 모델 게이트웨이가 집행한다. 에이전트의 존재, 책임자, 만료는 신원 원장이 정한다. 대화 내용은 따로 부여하고 감사하는 역할만 본다. 조사한 게이트웨이 가운데 초과 사용 승인 흐름을 내장한 곳은 없었다. 예산을 신원 속성으로 다루는 IdP도 확인되지 않았다. 그래서 그 빈자리는 Governance 원장이 맡는다. 이는 D-45(신원 정본 = Governance 원장)와 같은 방향이다.

1. **Governance 원장이 배분 · 에이전트 신원 · 위임의 유일한 정본이다.** 모델 게이트웨이 · Keycloak · 정책 엔진은 원장이 밀어 넣는 집행 지점이다.
2. **모델 게이트웨이는 사원 영역의 LiteLLM OSS로 시작한다(후보 A).** 사용자 · 키 · 예산은 원장 기반 프로비저닝 컨트롤러가 관리 API로 넣는다. 채택 조건은 §3.2에 둔다.
3. **배분 단위는 모델별 가중치를 곱한 "가중 토큰"이다(후보 B).**
4. **모든 사원에게 월 기본 할당을 준다.** 부서 · 프로젝트 풀은 원장이 관리하고, 승인된 추가분은 개인 상한을 올려 집행한다(후보 C).
5. **개인 에이전트는 소유자 할당에서 끌어 쓴다(후보 D).** 공용 에이전트는 단위 소유의 서비스 신원과 단위 풀을 쓴다(후보 E).
6. **에이전트 상태는 네 축으로 나눈다.** 실행 허가는 원장 축만 정한다. 건강은 콘텐츠 없이 계산한다.
7. **킬 스위치는 원장에서 시작해 VM에서 끝난다.** Backbone 보안 동결(D-39)은 HISS 수준에서 집행한다.
8. **데이터는 콘텐츠 · 행위 감사 · 사용량 세 층으로 나누고 섞지 않는다(후보 H).**
9. **에이전트 관리는 최상위 메뉴다. 다만 Admin Console이 아니라 회사 관리 콘솔에 둔다.** 구성 구역에 "에이전트", 배분 구역에 "AI 배분", Workspace에 "내 AI", Admin Console에는 "AI 공급"만 둔다.
10. **출시 전에 개인정보 영향평가와 노사협의회 협의를 마친다.** HR 용도 에이전트는 고영향 심사를 통과해야 만든다(후보 L).

## 2. 평면별 배치 (`제안`)

결정은 Governance, 집행은 Fabric의 사용 측, 공급은 Backbone, 강제 종료는 HISS에 둔다.

| 평면 | 맡는 일 | 구성 요소 | 볼 수 없는 것 |
|---|---|---|---|
| Backbone | 엔진과 용량 공급, 보안 동결(D-39) | 추론 엔진 엔드포인트(vLLM 등), GPU 용량, 자리 VM 용량 풀, 게이트웨이 이미지 버전 고정과 취약점 공지. Backbone 자체 AI는 Magpie(D-29) | 사원 콘텐츠, 가상 키, 게이트웨이 DB, 사원별 사용량 |
| Fabric (공급 측 Backbone · 사용 측 사원 영역) | 공유 집행 지점 | 모델 게이트웨이(LiteLLM), MCP · 도구 게이트웨이, 웹 이그레스 프록시, 깊이 2 위임용 토큰 브로커(후보 J), 영역별 콘텐츠 트레이스 저장소 | 공급 측은 사용 측의 데이터와 키를 보지 않는다 |
| Governance | 배분, 신원, 위임, 승계, 승인 | 원장(`model.usage` · `agent.seat` · 에이전트 레코드 · 위임 · 승계 큐), 프로비저닝 컨트롤러(원장 → LiteLLM · Keycloak · 정책 튜플), 행위 감사, 승인 워크플로 | 콘텐츠 |
| Workspace | 사용과 일상 제어 | 내 사용량, 내 에이전트, 승인함, 공용 에이전트 갤러리, 내 기록 보기 · 내보내기 · 삭제 | 다른 사원의 데이터 |
| HISS | 바닥 강제 | KubeVirt 자리 VM(D-51), Kata 헤드리스(D-52), 세 출구만 여는 네트워크 정책, VM 일시정지 · 정지 | — |

**D-29와의 긴장(후보 I).** D-29는 게이트웨이를 사원 영역에 둔다. 그러나 추론 엔진을 Backbone이 공급하면 프롬프트가 엔진을 지나간다. 게이트웨이 설정만으로는 운영자가 콘텐츠를 보지 못하게 할 수 없다. 엔진의 요청 로깅을 끄고, 엔진 페이로드를 Backbone 텔레메트리에 싣지 않고, 엔진 네임스페이스 접근을 제한해야 한다. 아니면 엔진을 사원 영역에서 돌려야 한다. 또 Backbone이 클러스터 관리자 권한을 갖는 한 "볼 수 없음"은 기술적 불가능이 아니라 **통제와 감사로 지키는 약속**이다. 시크릿을 영역이 쥔 키로 암호화하고 시크릿 접근을 감사해야 그 약속을 검증할 수 있다.

**게이트웨이 신원 연동.** 사원은 LiteLLM UI에 로그인하지 않는다. Workspace가 Keycloak으로 인증한 뒤, 원장이 발급한 사원별 · 에이전트별 가상 키로 게이트웨이를 부른다. 그러면 LiteLLM OSS의 SSO 5명 제한은 게이트웨이 관리자 몇 명에게만 걸린다. 헤더로 사용자 ID를 넘기는 방식은 업스트림 인증 프록시가 그 헤더를 덮어쓸 때만 안전하다.

## 3. 모델 게이트웨이

### 3.1 업계 비교

| 게이트웨이 | 사람 · 에이전트별 한도 | 금액 예산과 원장 | 자체 호스팅 | OpenSphere 관점의 걸림돌 |
|---|---|---|---|---|
| LiteLLM | 사용자 · 팀 · 조직 · 키 · 최종 사용자 | 있음(Postgres) | 가능(Postgres · Redis) | 디렉터리 연동과 감사 로그가 유료다. 2026년 보안 이력이 나쁘다 |
| Agent Router(구 Envoy AI Gateway) | 헤더 버킷 | 토큰만 | 가능(K8s) | 원장과 UI를 직접 만들어야 한다 |
| agentgateway | 헤더 · JWT 클레임 · 키 | 토큰만 | 가능(K8s) | 원장이 없다 |
| Kong | 컨슈머 · 컨슈머 그룹 | 정의한 비용 | 가능 | 필요한 기능이 Enterprise다 |
| Portkey | 메타데이터 | 있음 | 가능 | 예산 기능의 OSS 범위가 불명확하다. 인수 후 로드맵 위험(2차 출처) |
| Cloudflare · OpenRouter | 있음 | 있음 | 불가(SaaS) | 프롬프트가 외부 인프라를 지난다 |

모든 게이트웨이에 공통으로 **초과 사용 승인 흐름이 없다.** 승인은 바깥에서 만들고 관리 API로 예산을 올린다. 그 바깥이 Governance다.

LiteLLM OSS(MIT) 범위: 가상 키, 키별 예산과 속도 제한, 사원 기본 예산(`max_internal_user_budget` + `internal_user_budget_duration`), 지출 추적, 관리 UI. **Enterprise 범위:** 5명을 넘는 SSO, SCIM, JWT 인증, 감사 로그, 조직 · 팀 관리자 RBAC, 태그 예산, 모델별 키 예산, 소프트 예산 알림, 팀별 로깅.

### 3.2 LiteLLM 채택 조건 (후보 A)

2026년에 PyPI 공급망 침해(CVE-2026-33634), 인증 없는 SQL 인젝션(CVE-2026-42208), CISA KEV에 오른 원격 코드 실행(CVE-2026-42271), 관리자 탈취 결함이 이어졌다. 그래서 다음을 조건으로 둔다.

- 내부망 전용. 관리 UI와 관리 API는 외부에 노출하지 않는다.
- `-stable` 이미지, 버전 고정, 해시 검증. PyPI 직접 설치를 쓰지 않는다.
- MCP 테스트 엔드포인트와 pass-through 엔드포인트를 막는다.
- 패치 SLA를 정한다. Backbone이 버전 공지를 맡는다.
- DB 장애 시 열린 상태로 실패하지 않게 `allow_requests_on_db_unavailable`을 끈다.

### 3.3 콘텐츠를 남기지 않는 설정

- `store_prompts_in_spend_logs` 끔, `turn_off_message_logging: true`, `disable_error_logs: true`, `log_raw_request_response` 사용 안 함.
- `global_disable_no_log_param`을 켜서 클라이언트가 사용량 기록 자체를 건너뛰지 못하게 한다.
- 지출 메타데이터(사용자, 팀, 모델, 토큰, 비용)는 남는다. 배분과 차단에는 이것으로 충분하다.
- 사내 추론 엔진(vLLM 등)도 요청 로깅을 끈다. 게이트웨이 설정만으로는 부족하다.

## 4. 토큰 배분 (`제안`)

LiteLLM에서는 **팀에 속한 키에 소유자의 개인 예산이 적용되지 않는다.** 그래서 개인 기본 할당과 부서 풀을 같은 키에 겹쳐 걸 수 없다. 해법은 부서 풀을 게이트웨이가 아니라 원장의 개념으로 두는 것이다.

| 배분 대상 | 원장 개념 | LiteLLM 집행 | 비고 |
|---|---|---|---|
| 전 사원 기본 할당 | 회사 풀에서 사원별 월 할당 | `internal_user` + `max_internal_user_budget` + `internal_user_budget_duration: 30d` | 수치는 측정 후 정한다 |
| 부서 풀 | 부서별 월 풀. 구성원 상한 상향의 재원 | 게이트웨이 객체를 만들지 않는다. 승인 시 사용자 `max_budget`을 그 주기만 올린다 | 승인 흐름은 원장에 있다 |
| 프로젝트 풀 | 프로젝트별 기간 풀 | 프로젝트 팀과 팀 키 | 프로젝트 에이전트와 공동 작업 |
| 개인 에이전트 | 소유자 할당의 하위 배분 | 소유자 소유, `team_id` 없는 키, 키 `max_budget` 하위 상한 | 키 상한과 소유자 상한이 함께 걸린다 |
| 고부하 개인 에이전트(예외) | 부서 · 프로젝트 풀에서 별도 배정 | 에이전트 전용 키 예산 | 배분 구역 승인 필요 |
| 공용 에이전트 | 소유 단위 풀 | 단위 팀 아래 서비스 키 | 호출자별 공정 사용 상한은 `end_user` 예산으로 건다 |

- **단위(후보 B).** `model.usage`의 단위는 토큰이지만 모델마다 비용이 크게 다르고 LiteLLM 예산은 금액이다. 모델 등급별 가중치를 곱한 **가중 토큰**을 원장 단위로 쓰고, LiteLLM의 모델별 단가를 그 가중치로 설정해 게이트웨이의 "지출"이 곧 가중 토큰이 되게 한다. 사내 모델은 단가를 정하지 않으면 비용이 0으로 잡혀 속도 제한 말고는 막지 못한다. 이 동작은 LiteLLM 가격 설정 문서로 검증해야 한다.
- **기본 할당 수치.** 처음 4주는 높은 상한으로 측정만 한다. 그다음 사원별 분포의 중앙값과 75분위 사이에서 정하고, 분기마다 다시 맞춘다.
- **개인 에이전트 재원(후보 D).** 소유자 할당에서 끌어 쓰는 것이 기본이다. D-46의 교집합 원칙과 예산 원칙이 같아지고, 에이전트를 여러 개 만들어 할당을 부풀리는 일을 막는다. 에이전트 키에는 소유자가 정하는 하위 상한(예: 소유자 할당의 50%)을 둬서 폭주한 에이전트가 사원의 대화형 사용까지 막지 못하게 한다.
- **초과 사용.** 80%에 알림, 100%에 하드 스톱. 사원은 Workspace에서 추가 할당을 요청하고, 부서 책임자가 배분 구역에서 승인한다. 한도를 넘기는 바로 그 요청은 완료된다는 점을 운영 정책에 적는다.

## 5. 공용 에이전트 정의 (후보 E, `제안`)

지금까지 OpenSphere에는 개인 · 부서 · 프로젝트 에이전트만 있었다. **공용 에이전트는 부서 · 프로젝트 · 회사 중 한 단위가 소유하는 서비스 신원이다. 책임자는 그 단위의 Governance 책임자 역할이다.** 회사 에이전트는 회사 전체를 단위로 하는 공용 에이전트다.

| 실행 모드 | 실효 권한 | 근거 |
|---|---|---|
| 호출형(사원이 부름) | 에이전트 배정 ∩ 호출한 사원의 현재 권한 | 공용 에이전트가 권한 세탁 통로가 되지 않게 한다. 에이전트와 호출자 신원을 함께 담는 on-behalf-of 토큰과 같은 구조 |
| 자율형(예약 · 이벤트) | 배정 ∩ 단위 책임자 역할의 현재 권한 ∩ 자율성 위험 상한 | D-46의 상시 위임을 따르되 위임자를 사람이 아니라 역할로 둔다 |

- 역할 보유자가 바뀌어도 역할이 채워져 있으면 계속 돈다. 새 보유자에게 정해진 기간(예: 14일) 안에 재확인을 요구하고, 넘기면 일시정지한다.
- **역할이 비면 즉시 정지한다.** "책임자 없는 실행은 없다"는 원칙을 지킨다.
- 공용 에이전트는 사람의 키를 빌리지 않는다. 단위 팀 아래 서비스 키와 Keycloak 머신 클라이언트(D-45)를 갖는다.

**D-48 보완(후보 F).** 개인 에이전트의 퇴사 시 정지는 유지한다. 그 위에 소유자의 관리자를 승계 후보로 자동 지명하고, 수락 기한이 지나면 폐기한다. 떠난 사원의 기록과 메모리는 기본 삭제하고 업무 산출물만 넘긴다. 업계 선례(Microsoft Entra Agent ID)는 sponsor가 떠나면 관리자에게 자동 이관하고 에이전트를 계속 돌린다. OpenSphere는 정지를 유지하되 그 연속성 장점만 받아들인다.

## 6. 에이전트 상태와 건강 (`제안`)

업계 공통 상태 기계는 1차 출처에서 찾지 못했다. 한 축에 모두 넣으면 "VM은 떠 있는데 원장상 동결" 같은 조합을 표현할 수 없다. 그래서 네 축으로 나누고 **실행 허가는 원장 축만 정한다.**

| 축 | 정본 | 상태 값 | 누가 바꾸나 |
|---|---|---|---|
| 수명주기 | Governance 원장 | 요청됨, 활성, 일시정지, 예산 정지, 동결, 승계 대기, 만료, 폐기 | 소유자, 단위 책임자, 테넌트 관리자, 정책 자동화. 동결은 Backbone도(D-39) |
| 실행 | 하네스(OpenBot)와 워크플로 엔진 | 유휴, 실행 중, 승인 대기, 실패 | 런타임이 보고한다 |
| 인프라 | HISS(KubeVirt VMI, Kata 파드) | 프로비저닝, 실행, 일시정지, 정지 | 원장 상태에 맞춰 컨트롤러가 조정한다 |
| 건강 | 지표 계산 | 정상, 주의, 저하 | 임계값 규칙. 저하가 이어지면 자동 일시정지 |

건강 지표는 모두 메타데이터로 계산한다.

| 지표 | 출처 | 의미 |
|---|---|---|
| LLM 실패율 | 게이트웨이 실패 지표, 스팬 `error.type` | 모델 · 키 · 설정 문제 |
| 시간당 가중 토큰과 기준선 대비 편차 | 게이트웨이 토큰 · 지출 지표 | 폭주와 루프의 1차 신호 |
| 실행당 LLM 호출 수와 단계 수 | `invoke_agent` 스팬 | 루프 탐지 |
| 같은 도구 연속 호출 횟수 | `execute_tool` 스팬의 도구 이름 | 루프 탐지(인자 해시는 영역 안에서 계산) |
| 도구 오류율과 정책 거부 수 | 도구 게이트웨이, area shell 종료 코드 | 권한 설정 오류나 탐색 시도 |
| 이그레스 거부 수 | 웹 이그레스 프록시 | 유출 시도나 설정 오류 |
| `finish_reason` 분포 | 스팬 | 길이 초과 급증 |
| 승인 대기 체류 시간 | 워크플로 상태 | 사람 병목 |
| 하트비트 경과 시간 | 하네스 | 응답 없음 |
| 잔여 예산 | 게이트웨이 잔여 예산 지표 | 예산 정지 임박 |

이 지표는 콘텐츠를 드러내지 않지만 사람을 식별하게 할 수는 있다. Backbone 화면에는 가명 에이전트 ID와 단위 집계만 둔다. 게이트웨이 지표의 사용자 라벨은 수집 단계에서 지운다. 단위 보고에는 최소 인원 임계값을 둔다.

**관측 표준(후보 K).** OpenTelemetry GenAI 시맨틱 컨벤션은 2026년 11월 현재 아직 실험 단계다. 비용과 토큰의 정본 계수기는 게이트웨이 지표로 두고, 스팬은 버전을 고정해 정규화한다. 콘텐츠 속성(`gen_ai.input.messages` 등)은 기본으로 꺼져 있지만 OTel Collector에서도 한 번 더 지운다.

## 7. 킬 스위치 (`제안`)

신원 비활성화는 새 토큰 발급만 막는다. 이미 발급된 토큰은 만료될 때까지 산다. 그래서 VM 바깥의 집행 지점을 먼저 닫는다. 1~4단계는 에이전트 프로세스가 침해됐거나 응답하지 않아도 작동한다.

| 순서 | 동작 | 집행 지점 | 효과 |
|---|---|---|---|
| 0 | 원장 상태를 "동결"로 바꾸고 사유 · 요청자 · 범위를 기록한다 | Governance | 모든 후속 단계의 근거. 재활성화도 원장에서만 |
| 1 | 가상 키를 차단하거나 예산을 0으로 만든다 | 모델 게이트웨이 | 사고가 멈춘다 |
| 2 | 도구와 area shell을 전부 거부한다 | MCP · 도구 게이트웨이 | 행동이 멈춘다 |
| 3 | 웹 이그레스를 끊는다 | 이그레스 프록시, HISS 네트워크 정책 | 외부 유출이 막힌다 |
| 4 | Keycloak 클라이언트를 비활성화하고 세션 · 리프레시 토큰을 회수한다 | Keycloak | 새 토큰 발급이 막힌다 |
| 5 | 워크플로에 취소 신호를 보내고 보상 작업을 돌린다 | 워크플로 엔진 | 정상 정리 |
| 6 | VM을 일시정지(포렌식 보존)하거나 정지한다 | HISS(KubeVirt) | 강제 종료 |
| 7 | 행위 감사 스냅샷을 남기고 소유자 · 단위 책임자에게 알린다 | Governance | 증거와 책임 확보 |

- **범위:** 개별 에이전트, 템플릿(같은 하네스 버전이나 등급), 단위, 회사 전체.
- **권한:** 소유자는 자기 에이전트에 0~6단계, 단위 책임자는 단위 범위, 테넌트 관리자는 회사 범위까지.
- **Backbone 보안 동결(D-39)은 원장이나 게이트웨이 관리 API가 아니라 HISS 수준에서 집행한다.** 자리 VM에서 게이트웨이로 가는 경로를 네트워크 정책으로 끊거나 VM을 일시정지한다. 이렇게 해야 D-29("키와 데이터를 공유하지 않는다")를 지키면서 비상시에 멈출 수 있다.
- 1단계의 반영 지연(게이트웨이 키 인증 캐시)은 실측한다. 즉시 반영된다고 가정하지 않는다.
- 자동 차단: 10분 지출이 기준선의 N배를 넘거나 루프 지표가 임계를 넘으면 1단계와 5단계로 일시정지하고 소유자에게 알린다. OWASP의 무제한 소비(LLM10)와 폭주 에이전트(ASI10) 대응에 해당한다.

## 8. 데이터 세 층 (후보 H, `제안`)

| 층 | 담는 것 | 소유 · 열람 | 저장 위치 | 보존(권고) | Backbone |
|---|---|---|---|---|---|
| 콘텐츠 | 프롬프트, 응답, 에이전트 메모리, 도구 입출력, 내용 있는 트레이스 | 사원 본인. 공용 에이전트는 단위 | 영역 소유 저장소, 영역이 쥔 키로 암호화. 트레이스는 영역별 프로젝트나 인스턴스 | 기본 30~90일, 사원이 조정 · 삭제 | 볼 수 없다 |
| 행위 감사 | 누가, 어느 에이전트, 어느 도구, 대상 자원 등급, 위임 체인, 승인 여부, 정책 결정 | Governance, 준법 역할 | 변조 감지 저장소. 원문은 해시나 참조만 | 6~12개월. EU 고위험이면 최소 6개월 | 볼 수 없다 |
| 사용량 | 사원 · 에이전트 · 단위별 가중 토큰과 지출 | 본인, 배분 승인자, 단위 집계 | 원장과 게이트웨이 DB | 일 단위 3개월, 월 단위 12개월 | 엔진 · 모델 단위 집계만 |
| 운영 지표 | 엔진 지연, 오류, 용량, 배치 상태 | Backbone | Prometheus 계열 | 운영 표준 | 본다 |

- 보존 기간은 법정 최소가 아니라 권고다. PIPC의 에이전트 안내서(2026년 말 예정)가 나오면 다시 본다.
- 콘텐츠 열람 경로는 Admin Console에 아예 두지 않는다. 비상 열람은 법적 보존 요구나 확인된 보안 사고에만 허용하고, CISO · CPO 이중 승인에 노무 또는 법무를 더한다. 열람 기록은 지울 수 없게 남긴다.
- 게이트웨이 DLP는 주민등록번호 · 카드 번호 · 비밀 키를 외부 모델로 가기 전에 가린다. 기록은 "어떤 범주가 걸렸다"까지만 남기고 관리자 행동 감시 알림으로 쓰지 않는다.
- 워크플로 이력(Temporal 등)에는 도구 입출력이 남는다. 영역별 네임스페이스나 영역 키 기반 페이로드 암호화를 쓴다. 이 기능은 1차 문서로 확인하지 못했다.

## 9. 접근 지점별 메뉴 (`제안`)

에이전트 관리는 **최상위 메뉴**다. Microsoft 365 관리 센터, Google Gemini Enterprise, Atlassian, Glean이 모두 관리 콘솔 최상위에 Agents를 두고, 비용과 배분은 그 옆의 별도 영역에 둔다. 이는 회사 관리 콘솔의 구성 구역과 배분 구역 분리(D-84)와 그대로 맞는다.

| 접근 지점 | 최상위 메뉴 | 하위 화면 | 사용자 |
|---|---|---|---|
| Admin Console | **AI 공급** | 엔진 상태(지연, 오류율, 배치 상태), GPU · 자리 VM 용량, 게이트웨이 버전과 패치 상태, 이그레스 프록시 상태, 보안 동결(전역 또는 등급 단위) | Backbone 운영자 |
| 회사 관리 콘솔 · 구성 구역 | **에이전트** | 개요(승인 대기 · 승계 대기 · 위험 · 예산 임박 카드), 레지스트리(개인 에이전트 포함, 메타데이터만), 템플릿과 하네스(OpenBot 버전, 자율성 위험 상한 등급), 도구와 연결(MCP 허용 목록, 이그레스 정책), 정책(승인 등급, 고영향 분류), 일시정지와 차단 | 테넌트 관리자 |
| 회사 관리 콘솔 · 구성 구역 | **AI 모델** | 모델 카탈로그(사내 · 외부), 모델 가중치, DLP와 가드레일, 콘텐츠 보존 기본값 | 테넌트 관리자 |
| 회사 관리 콘솔 · 구성 구역 | **감사** | 행위 감사 검색, 비상 열람 요청과 이중 승인 기록 | 별도 준법 역할 |
| 회사 관리 콘솔 · 배분 구역 | **AI 배분** | 회사 · 부서 · 프로젝트 풀, 기본 할당, 추가 배분 요청함, 자리(`agent.seat`) 배정, 에이전트 소유 · 후원 · 위임, 승계 큐, 재인증 캠페인, 단위별 사용 보고 | Governance 책임자 |
| Workspace | **내 AI** | 내 사용량(잔여 할당, 에이전트별 소비), 내 에이전트(상태, 일시정지 · 재개 · 정지, 위임 만료 갱신, 기록과 메모리 보기 · 삭제), 승인함, 공용 에이전트 갤러리, 내가 책임지는 공용 에이전트, 요청(추가 할당, 에이전트 신청) | 전 사원 |

- **Admin Console에 에이전트 메뉴를 두지 않는다.** Backbone에 필요한 것은 "자리가 몇 개, 어떤 상태인가"라는 익명 집계와 전역 동결뿐이다. 누가 어떤 에이전트를 가졌는지는 알 필요가 없다(D-29, D-39).
- "에이전트"와 "AI 배분"은 같은 레지스트리 객체를 보고 개요 카드로 서로 이어진다.
- Admin Console의 기존 "AI Agent · OpenClaw"는 Backbone 자신의 운영 에이전트다. 사원 에이전트와 다르다. 이름이 섞이지 않게 화면에 구분을 적는다.
- 부서 책임자가 구성원 한 명 한 명의 소비를 상시로 보는 화면은 만들지 않는다. 개인 단위 정보는 본인이 추가 할당을 요청할 때 요청서에 붙는 방식으로만 드러난다(후보 M).

| PIPC 에이전트 안내서(가칭, 2026년 말 예정) | 자율 행동과 사람 승인의 경계, 로그 · 메모리 보존 · 삭제, 위임 사용의 입증 | 행위 감사로 위임 사용을 입증, 메모리 보존 · 삭제 기능 | 안내서 공개 후 재검토 |
| 근로자참여법 제20조 제1항 제14호 | 상시 30명 이상 사업장의 근로자 감시 설비 설치는 노사협의회 협의 사항. 감시 효과가 있으면 감시 설비로 본다 | 사용량 · 상태 지표의 목적(비용 배분 · 보안), 열람자, 징계 목적 재사용 금지를 협의 | 1단계 출시 전 |
| EU AI Act 제26조(EU 법인 · 직원이 있을 때) | 고용 · 근로자 관리 고위험 의무는 2027-12-02부터(AI Omnibus). 감독자 지정, 로그 최소 6개월, 근로자 고지 | 에이전트 "고위험" 등급, 행위 감사 보존 연장 | 2027-12-02 전 |

통제 목록으로는 OWASP Agentic Top 10(2025-12-09), 싱가포르 에이전트 AI 거버넌스 프레임워크(2026-01-22), ISO/IEC 42001을 쓴다. 의무가 아니라 위험 등록부와 설계 점검표로 쓴다. 사내 전용 플랫폼이 AI 기본법 고지 의무 대상인지는 확인하지 못했다. 비용이 낮으므로 지키는 쪽을 권한다.

## 11. 단계 (`제안`)

D-61이 1단계를 게이트웨이 사용 배분으로 한정했으므로 순서는 다음과 같다.

| 단계 | 목표 | 산출물 | 완료 기준 |
|---|---|---|---|
| 0. 결정과 기반 | 구조를 고정한다 | 결정 기록(A · B · E · H · I 우선), 영향평가, 노사협의회 협의, LiteLLM 보안 기준선 | 결정 기록 승인, 협의 완료 |
| 1. 전 사원 토큰 공급 | 사원이 할당 안에서 모델을 쓴다 | 사원 영역 LiteLLM, 원장 → 게이트웨이 프로비저닝, 4주 측정 후 기본 할당, 부서 풀 상향 승인, Workspace "내 사용량", 배분 구역 "AI 배분", Admin Console "AI 공급", DLP 기본 규칙, 콘텐츠 비저장 설정 | 할당 · 차단 · 승인이 원장 기준으로 일치. Backbone 화면에 개인 식별 정보 없음 |
| 2. 개인 에이전트 | 사원이 자기 에이전트를 안전하게 쓴다 | 자리 VM(D-51), OpenBot(D-50), 원장 에이전트 레코드, 에이전트별 Keycloak 머신 클라이언트, 소유자 하위 상한, 네 축 상태, 킬 스위치 0~7단계, 승인함, 행위 감사, 퇴사 승계 흐름, 구성 구역 "에이전트" | 킬 스위치 훈련에서 1~3단계 반영 시간 실측. 퇴사 시나리오 통과 |
| 3. 공용 에이전트와 자율 실행 | 단위 에이전트와 상시 위임을 연다 | 단위 소유 서비스 신원, 역할 기반 후원, 호출형 · 자율형 권한 계산, Kata 헤드리스(D-52), 깊이 2 위임용 토큰 브로커(D-47), 재인증 캠페인, 비활성 정책, 이상 탐지 자동 정지 | 위임 교집합이 정책 엔진 테스트 통과. 재인증 주기 운영 |
| 4. 고도화와 준법 | 규제와 표준 변화를 흡수한다 | 고영향(HR) 심사 게이트, EU 고위험 등급(해당 시), PIPC 안내서 반영, OTel GenAI 안정판 이전, ISO 42001 적용성 검토 | 규제 점검표가 닫힌다 |

**가장 큰 위험은 원장에서 집행 지점으로 이어지는 배관이다.** 게이트웨이 · Keycloak · 정책 엔진 · HISS가 원장과 어긋나는 순간 "원장상 정지인데 실제로는 도는" 에이전트가 생긴다. 프로비저닝 컨트롤러는 주기적으로 대사(reconcile)하고 어긋남을 개요 카드로 드러낸다. 그 밖의 위험은 LiteLLM 자체의 보안 이력, preview · 실험 단계 의존(Keycloak 위임, OTel GenAI, MCP 확장, Temporal LangGraph 플러그인), 과잉 통제로 인한 우회 사용이다. 기본 할당과 개인 에이전트 생성은 쉽게 하고, 위험은 자율 실행과 외부 행동에서 막는다.

## 12. 결정 후보 (모두 `제안`)

| 후보 | 결정할 내용 | 권고안 | 결정 전 확인 |
|---|---|---|---|
| A. 모델 게이트웨이 확정 | LiteLLM OSS + 자체 프로비저닝, LiteLLM Enterprise, Agent Router + 자체 원장 중 선택 | LiteLLM OSS + 원장 프로비저닝으로 시작하고 §3.2 조건을 둔다 | 현재 안정판의 CVE 반영 여부, Enterprise 견적 |
| B. 배분 단위 | 가중 토큰과 모델 가중치 산정법 | 모델 등급별 가중치, 게이트웨이 단가를 가중치로 설정 | LiteLLM 커스텀 단가 동작 |
| C. 부서 풀 집행 | 원장 상향 방식과 게이트웨이 팀 방식 | 원장 상향 방식 | 대량 갱신 시 관리 API 성능 |
| D. 개인 에이전트 재원 | 소유자 할당 하위 배분과 별도 키 | 하위 배분이 기본, 별도 키는 승인된 예외 | 하위 상한 기본 비율 |
| E. 공용 에이전트 정의 | 단위 소유 서비스 신원, 역할 후원, 호출형 · 자율형 권한 | §5의 정의 | 역할 보유자 교체 시 재확인 기한 |
| F. 승계 보완(D-48 개정) | 관리자 자동 후보, 수락 기한, 떠난 사원 데이터 처리 | 정지 유지, 관리자를 후보로 지명, 기한 후 폐기, 메모리 기본 삭제 | 인사 · 노무 검토 |
| G. 비활성과 재인증 | 비활성 기간, 재인증 주기 | 비활성 시 일시정지, 만료 전 알림과 자동 만료 | 운영 부담 |
| H. 데이터 세 층 보존 | 각 층의 기간, 비상 열람 절차 | 콘텐츠 30~90일, 행위 감사 6~12개월, 이중 승인 비상 열람 | PIPC 안내서, 안전성 확보조치 기준 |
| I. 엔진의 콘텐츠 경계 | Backbone 공급 엔진을 지나는 프롬프트 처리 | 엔진 요청 로깅을 끄고 접근을 제한하거나, 엔진을 사원 영역에서 운영 | D-29와의 정합성 |
| J. 깊이 2 위임 구현 | Keycloak SPI와 외부 토큰 브로커 | 외부 토큰 브로커로 중첩 `act`와 교집합 계산. Keycloak 26.8의 위임은 preview이고, 표준 토큰 교환이 위임 클레임이 있는 토큰을 거부한다 | Keycloak 실제 동작 검증 |
| K. 관측 스키마 | OTel GenAI 버전 고정과 정본 계수기 | 비용 · 토큰은 게이트웨이 지표가 정본, 스팬은 버전 고정해 정규화 | 계측 라이브러리별 설정 차이 |
| L. 고영향 용도 게이트 | HR 등 고영향 용도 분류와 심사 | 생성 시 용도 선언, 고영향은 심사 후 생성 | 법률 검토 |
| M. 개인 단위 지표 공개 범위 | 누가 어떤 수준의 사용량을 보는가 | 본인 전체, 승인자는 요청 시점에만, 단위 집계는 최소 인원 임계값 | 노사협의회 협의 |
