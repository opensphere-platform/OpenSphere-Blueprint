Fabric은 공급되는 모든 부품의 집합이고, 공유 서비스는 그 안에서 엔진들이 쪼개 나눠 받는 바탕 묶음이다. 제안

  • Fabric 안에는 네 묶음이 있다: 기반 · 배포 지원 · 공유 서비스 · 엔진.
  • 엔진(Stalwart)은 공유 서비스(PostgreSQL · Samba AD · OpenSearch · Keycloak)를 받아 기능(메일)을 만든다.
  • 테넌트는 Fabric이 아니다. 테넌트는 Fabric의 공유 서비스와 엔진을 어셈블리로 엮어 리소스 유형을 내놓는 회사 쪽 구성이다.
  • Fabric을 말할 때는 "누가 공급하고 누가 쓰나(두 얼굴)", 공유 서비스를 말할 때는 "무엇을 쪼개 나눠 주나(Claim·연결·용량)"를 따진다.

네 묶음의 두 얼굴

Fabric의 모든 묶음은 공급 면(Backbone)과 사용 면(테넌트)을 함께 가진다. 경계는 묶음과 묶음 사이가 아니라 각 묶음 한가운데의 인도 지점을 지난다.

묶음공급 면 · Backbone인도 지점사용 면 · 테넌트
엔진엔진 버전, 이미지, 호환 행렬엔진 인스턴스엔진 설정, 관리자 역할, 데이터
공유 서비스Provider, operator, 공급 풀, 인스턴스 수명주기Claim → 연결(Binding)연결 자격(DB·역할·버킷·읽기 계정), 데이터
배포 지원Argo·Crossplane 엔진영역 인스턴스영역 Argo AppProject, 배포 서명 키
기반노드, 클러스터, 네트워크, 저장 엔진, 영역 사이 칸막이네임스페이스 생성네임스페이스 안의 내용, 영역 내부 정책

네 층의 이름과 정의하는 곳

사람에게 닿기까지 네 층을 지난다. 앞의 둘은 Fabric 안, 뒤의 둘은 테넌트 안이다. 제안

층이름예정의(만드는 곳)사용(고르는 곳)
1공유 서비스PostgreSQL, Samba AD, Keycloak, OpenSearchAdmin 카탈로그(공급사 릴리스 → Admin 채택)어셈블리가 연결로 받는다
2엔진Stalwart, Mattermost, Odoo, GitLabAdmin 카탈로그어셈블리에 들어간다
3어셈블리메일 = Stalwart + PostgreSQL + Samba AD + OpenSearch + KeycloakAdmin 카탈로그회사 관리 콘솔 · 구성 구역에서 선택·용량 설정
4리소스 유형mail.mailbox, calendar.calendar어셈블리 정의에 포함회사 관리 콘솔 · 배분 구역에서 할당 → Workspace

정의는 Admin(Backbone)에서, 사용은 테넌트에서 한다. 정의에는 회사 데이터나 키가 없으므로 Backbone이 만들어도 B-2·B-3을 어기지 않는다. Backbone은 고를 수 있는 선택지만 공급하고, 무엇을 고를지는 회사가 정한다. 외부 리소스는 Admin 카탈로그의 연결기 틀에 회사가 값만 채워 편입한다. 회사가 만든 앱(사원 앱 3단계)은 어셈블리가 아니라 사원 앱 실행 환경 위의 앱이다.

혼동하기 쉬운 말

Fabric ≠ 공유 서비스Fabric은 네 묶음 전체, 공유 서비스는 그중 하나. "PostgreSQL은 Fabric의 공유 서비스다", "Stalwart는 Fabric의 엔진이다".
Fabric ≠ 테넌트Fabric은 공급되는 부품, 테넌트는 그 부품을 엮은 회사 쪽 구성. 테넌트는 회사 하나(D-83).
구성요소어셈블리 안에 들어간 공유 서비스 인스턴스와 엔진 인스턴스를 함께 부르는 말. 종류를 가릴 때는 공유 서비스, 엔진이라고 쓴다.
카탈로그 정의 ≠ Governance 정의카탈로그 정의는 Admin의 조합 틀(어셈블리를 어떻게 엮나), Governance 정의(D-27)는 배분 구역의 정책(누구에게 어떤 조건으로 주나).
제안 표시 항목(네 묶음, 네 층의 이름, 카탈로그 정의 위치)은 아직 결정 대장에 올리지 않았다. 관련: 네 면 구조 · 테넌트 구조 · 용어 대응표 · 어셈블리 카탈로그 · 테넌트·어셈블리 구성 명세
