# 업무 데이터 환경 · Data 거버넌스 계약 v0.1

**상태:** 2026-11-20 보스의 제품 목적 설명과 청사진 보강 요청을 반영한 명세 보강안이다. 제품 목적은 요청에 따른 기준이며, 아래 상세 필드·수용 시험은 구현 계약 제안이다. 새 D-결정 번호, 제품 선정, 코드·운영 적용 승인을 만들지 않는다.
**기존 관계:** D-82(구성과 배분), D-83(회사), D-84(접근 지점), D-21(회수), D-33(보존)을 유지한다. 기존 공급 명세·외부 리소스 통제 등급을 대체하지 않는다.

## 1. 제품의 목적과 제공 단위

> **OpenSphere는 MES·그룹웨어·메일 등의 업무 데이터 환경을 구성하고, 조직 정책과 사용자 권한에 따라 제공·변경·회수하는 통합 업무 플랫폼이다.**

업무 데이터 환경은 업무 애플리케이션, 업무 데이터, 제품 고유의 업무 규칙, 허용된 데이터 범위와 행위, 실제 사용 경로가 함께 준비된 환경이다. PostgreSQL·저장소·VM·모델은 이를 실현하는 기반 또는 사용 수단이다. 자원 공급 기능을 없애는 것이 아니라 제품 전체의 최종 결과와 구별한다.

OpenSphere에서 Data 거버넌스는 이 환경에 대한 조직 정책, 데이터의 소유·보존 책임, 사용자·에이전트의 허용 범위, 부여·변경·회수와 실제 반영 상태를 관리하는 제품 전체의 지향점이다. 영문 **Governance**는 그중 정책·할당·판단·대조를 담당하는 제품이다. Governance가 설치·조립·모든 업무 규칙까지 담당한다는 뜻이 아니다.

IaaS + SaaS는 제공 범위를 설명하는 보조 표현이다. 인프라를 내부 운영한다는 사실만으로 IaaS 제공이라고 부르지 않는다. 데이터 품질·계보 등 일반적 데이터 거버넌스의 모든 기능을 이미 제공한다고 주장하지 않는다.

## 2. 책임 경계

| 주체 | 책임 | 완료의 의미 |
|---|---|---|
| Backbone / HISS | 기반 설치·운영·공급·업데이트·독립 복구 | 기반·공급 경로 검증. 업무 환경 전체 완성은 아님 |
| Fabric | 엔진·공유 서비스와 선언된 집행 능력 | 필요한 인스턴스와 연결 능력 제공 |
| 테넌트 관리자 / 어셈블리 | 목적에 맞는 인스턴스·전용 신원·자격·연결·설정·초기화·검증·수명주기·용량 구성 | 배분 가능한 서비스와 리소스 유형·용량 인계 |
| Governance | 조직·직무·대상·행위·조건에 따른 정책과 배분, 변경·회수·대조 | 의도한 권한과 제품별 실제 효과의 일치 확인 |
| 업무 제품 / 집행 지점 | API·객체·레코드·업무 행위에서 실제 권한 강제 | 허용 요청 성공, 금지 요청 거절 |
| Workspace | 회사 기본 앱·통합 진입과 부여된 환경 사용, 권한 안의 앱·에이전트 활용 | 사용자가 별도 DB 자격 조립 없이 허용된 업무 수행 |

어셈블리는 단순 제품 목록·설치 묶음이 아니다. OSR의 서명된 비실행 어셈블리 정의와 실제 구성·검증된 서비스 인스턴스를 구별한다. 설치·구성 권한은 업무 데이터 열람 권한을 자동으로 주지 않는다. Backbone 기능의 Configuration 배치와 상위 제품 경험 분리는 유지한다.

## 3. 업무 권한 계약

리소스 유형의 기존 quota·actions·provisioning 계약에 아래 의미를 함께 명세한다. **아래 항목은 논리 계약 제안이며 현재 파서·API가 지원하는 YAML 필드라고 주장하지 않는다.** 업무 범위가 없는 순수 기반 자원은 해당 없음과 이유를 기록한다.

| 항목 | 필수 의미 |
|---|---|
| 업무 목적·정본 | 제공할 업무, 데이터 소유 조직, 정본 제품·객체 종류, 보존 책임자 |
| 주체·범위 | 사용자·조직·프로젝트·서비스·에이전트의 안정 ID, 공장·공정·문서·메일함 등 대상 ID와 범위 |
| 행위·조건 | 조회·생성·수정·승인·공유·내보내기 등 제품 행위, 조건·상속·명시적 거부 규칙 |
| 제품별 대응 | 공통 역할/정책 revision → 제품 내부 ACL·그룹·레코드 규칙·행위 권한의 정확한 매핑과 미지원 항목 |
| 판단·집행 | 정책 판단 주체, API/제품 내 집행 지점, 직접 URL·API 등 우회 경로의 통제, 캐시·세션·토큰 처리 |
| 투영·관측 | 요청·할당 ID, 제품별 desired/observed revision, 확인 API·증거, 실패·unknown·재개 방법 |
| 수명주기 | 부여·이동·위임 종료·퇴사 시 회수 범위, 시간 목표·실측, 데이터 보존·인계·삭제의 별도 절차 |
| 누출 방지 | 검색 결과·요약·알림·에이전트가 원본의 데이터 범위를 넘지 않는 조건. 미지원 경로는 통합 완료 범위에서 제외 |

제품 내부의 생산 규칙·결재 절차·정본을 중앙에 재구현하거나 모든 데이터를 한 DB에 합치지 않는다. 기존 제품의 권한 기능과 API를 우선 이용한다. SCIM 계정·그룹 동기화나 SSO 연결만으로 레코드·행위 통제를 구현했다고 판정하지 않는다.

**예시(제품 선정·MES 구현 확정 아님):** 생산담당 역할은 담당 공장 작업지시의 조회·실적 등록을 허용하되 타 공장 조회·품질 승인에는 별도 권한을 요구한다. 문서 제품에는 해당 프로젝트 폴더의 읽기/편집으로, 메일 제품에는 지정 공유 메일함 권한으로 각각 대응한다. 메일함의 GB 할당과 메일 내용의 읽기 권한은 서로 다른 계약이다.

## 4. 변경과 부분 실패

1. 조직·직무 변경에서 제품별 권한 차이를 계산하고 정책 revision·영향·승인 근거를 남긴다. 직접 할당의 재검토는 기존 규칙을 따른다.
2. 제품별 반영 상태를 따로 관측한다. API 접수·객체 저장·SSO 성공은 실제 데이터 권한 적용 성공이 아니다.
3. 하나의 제품이라도 확인되지 않으면 환경 전체를 완료로 표시하지 않는다. 적용 완료·지연·실패·unknown과 영향을 받는 데이터 범위를 표시한다.
4. 회수 실패 시 검증된 세션/토큰/진입 차단 수단을 적용하고 재시도·운영자 대응을 추적한다. 공통 진입 차단만으로 직접 API 세션도 차단됐다고 주장하지 않는다. 안전한 차단을 보장할 수 없는 경로는 미해결 위험으로 남긴다.
5. 접근 회수와 데이터 삭제를 분리한다. 공유 데이터·감사·소유 책임을 보존하고, 소유자 인계와 영구 삭제는 별도 승인·정책에 따른다.

## 5. 제품 수준 종단 수용 시험

합성 데이터·시험 신원으로 실시한다. MES가 없으면 지원 가능한 제품의 레코드 범위로 먼저 실증하되 MES 검증 완료로 바꾸어 부르지 않는다. 공급 시험을 대체하지 않고 그 위에 추가한다.

| ID | 시나리오 | 필수 성공·거절 증거 |
|---|---|---|
| BD-E1 | 입사·직무 배정 | 제공된 기본 앱에서 담당 범위 조회·등록 성공, 타 공장/프로젝트·무권한 승인 거절 |
| BD-E2 | 직접 접근 | 메뉴 숨김과 무관하게 직접 URL·API·객체 ID 변경으로도 금지 데이터 거절 |
| BD-E3 | 부서·담당 이동 | 새 범위 부여, 이전 파생 권한 회수, 문서·공유 메일 등 제품별 반영과 직접 할당 재검토 확인 |
| BD-E4 | 위임·에이전트 | 사용자 권한과 위임 범위의 교집합만 허용, 위임 종료 후 기존 세션·직접 API 재사용 거절 |
| BD-E5 | 퇴사 | SSO 차단·앱 회수의 기존 D-21 목표 및 실측, 직접 API·장기 세션의 차단, 회사 데이터 보존·소유 인계 |
| BD-E6 | 부분 실패·재개 | 한 제품 반영 실패·응답 유실을 주입, 전체 완료 오표시 없음, 노출 범위·차단·재개 결과 추적 |
| BD-E7 | 검색·알림·요약 | 해당 기능이 있으면 원본 접근 불가 데이터가 결과·미리보기·에이전트 응답에 나오지 않음. 미구현이면 미검증 표시 |
| BD-E8 | 변경·업데이트 후 재검증 | 정책·어댑터·제품 버전 변경 뒤 허용/거절·회수 시험 재수행, 이전 성공 자동 승계 금지 |

증거에는 정의/어셈블리/제품 버전, 정책 revision, 시험 주체·대상 ID(합성), 요청·할당·상관 ID, 기대/실제 결과, 집행 지점, 회수 측정 시간, 실패·미검증 범위를 남긴다. 비밀번호·토큰·실제 업무 원문은 남기지 않는다.

## 6. 완료 단계와 첫 납품

- **공급 검증:** DB·인스턴스·자격·연결의 실제 효과 확인.
- **서비스 구성 검증:** 어셈블리 초기화·연결·기능 확인, 리소스 유형·용량 인계.
- **업무 권한 통합 검증:** 선언한 제품·범위에서 허용·거절·변경·회수·부분 실패 시험 통과.
- **사용자 업무 환경 수용:** Workspace의 실제 업무 진입부터 위 시험까지 통과. 운영 안정성·부하·복원은 각 별도 검증 범위를 명시.

OSR에 등록 가능, 설치 가능, Data 거버넌스 통합 완료를 구별한다. 기존 managed/federated/referenced 등급은 그대로 두고, 통합 시험 범위·미지원 행위·미검증 경로를 함께 표시한다. 관리자가 위험을 인지했다는 이유만으로 미검증 경로를 통합 완료로 바꾸지 않는다.

첫 납품은 기존 Fabric 공급 수직 경로를 유지하면서 **대표 업무 제품 한 개의 세부 데이터 범위·행위·회수**를 먼저 입증한다. 이어 문서·메일 등 두 번째 제품과 조직 이동을 연결해 제품 간 일관성을 입증한다. 새 플랫폼이나 제품 도입은 이 문서만으로 승인하지 않는다.
