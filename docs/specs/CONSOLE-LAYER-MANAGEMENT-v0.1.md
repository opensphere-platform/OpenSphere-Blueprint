## 1. 왜 필요한가

D-89로 레이어(HISS · Fabric · Governance · Workspace)는 고정된 자리가 됐다. 그런데 운영자가 레이어 전체를 한눈에 보거나 조정할 곳이 없다.
- 레이어마다 무엇이 설치돼 있고, 무엇을 갱신할 수 있는지 보이지 않는다.
- 무엇이 막혀 있는지(보류된 선언, 실패한 계획, 실행 조건)도 보이지 않는다.
- 쓰지 않는 레이어를 레일에서 감추거나, 준비되지 않은 레이어의 설치를 막을 방법이 없다.
- 레일 아이콘이 빌드에 고정돼 있다. 2026-11-23에는 Governance · Workspace 아이콘 파일이 빌드에 실리지 않아 깨졌다. `angular.json`이 아이콘 4개만 복사했기 때문이다.

## 2. 원칙

- **레이어는 만들거나 지우지 않는다.** 계약(D-89)이 정한 레이어에 옵션만 준다.
- **옵션은 설치 판정과 권한을 우회하지 않는다.**
  - 설치를 닫아도 이미 설치된 패키지는 그대로 동작한다. 내리기(stop)는 언제나 할 수 있다.
  - 숨긴 메뉴와 레이어도 직접 주소와 섹션 홈 목록에는 남는다. 숨김은 보안 경계가 아니다.
- **바뀐 것은 원장에 남는다.** 누가 · 언제 · 무엇을 · 왜(사유)를 기록한다. 판(revision)으로 동시 수정을 막는다.
- 갱신 채널(edge · stable)과 승인 수준(예: HISS 두 사람 승인)은 **이번 범위가 아니다.** 따로 논의한다.

## 3. 화면 위치

- 설정 → OSR 묶음에 **"레이어"**를 둔다(스토어 · OSR 옆). 주소는 `#/configuration/osr/layers`, 레이어 세부는 `#/configuration/osr/layers/<layer>`이다.
- 각 섹션 홈에도 "레이어 관리" 링크를 둔다. 관리자 세션에게만 보인다.

## 4. 1단계 — 레이어 현황(읽기 전용, 새 상태 없음)

### 4.1 목록

| 칸 | 내용 |
|---|---|
| 레이어 | 아이콘 + 이름 |
| 정의 | 한 줄 정의(네 면 구조 §2) |
| 설치 | 설치된 패키지 수 / 스토어에 있는 패키지 수 |
| 갱신 | 갱신할 수 있는 패키지 수 |
| 상태 | 정상 · 확인 필요(실패한 계획, `withheld`, `unknown` 인스턴스) · 읽지 못함 |
| 설치 허용 | 열림 · 닫힘(2단계 옵션, 1단계에서는 늘 "열림") |
| 바로가기 | 섹션 홈 · 이 레이어로 거른 스토어 |

- **Backbone 행:** 스토어 밖이다. 지금 판을 보이고, Backbone 현황으로 가는 링크만 둔다. 옵션은 없다.

### 4.2 레이어 세부

- **묶음(자리):** D-89 §4.2의 묶음과 각 묶음을 쓰는 패키지 · 메뉴 항목
- **패키지:** 이름(로고) · 설치된 판 · 채널의 판 · 상태 · 마지막 적용 시각
- **막힌 것**
  - 보류된 확장 선언(`withheld`)과 그 이유
  - 주소 충돌로 거절된 계획
  - 실패 · 미확정 계획과 `unknown` 인스턴스
- **실행 조건**
  - 모듈 실행부 준비
  - (HISS) 관측 바닥 설치 여부
  - (Fabric) 실행부가 기대는 HISS 엔진 설비 상태(읽을 수 있는 만큼)
- **최근 변경:** 이 레이어 패키지의 계획 · 승인 · 적용 이력(원장)
- 원천을 읽지 못한 칸은 "읽지 못함"이다. 값을 지어내지 않는다.

### 4.3 서버

- `GET /console-api/osr/layers`, `GET /console-api/osr/layers/<layer>`. 관리자 세션 · `OsrRead`이다.
- 기존 원장 · 스토어 · 메뉴 조회를 모아 돌려준다. 새 표를 만들지 않는다.

## 5. 2단계 — 레이어 옵션

### 5.1 옵션

| 옵션 | 값 | 기본값 | 바꾸는 조건 |
|---|---|---|---|
| `railVisible` | 레일 표시 여부 | 켜짐 | 관리자 세션 + 사유 |
| `icon` | 레일 · 섹션 홈 아이콘. **호스트가 Console에 함께 넣은 Carbon 아이콘 목록**에서 고른다(§6) | 레이어별 기본 아이콘 | 관리자 세션 |
| `menu` | 같은 묶음 안의 항목 순서, 항목 숨김(D-89 §6) | 패키지 `order`, 모두 보임 | 관리자 세션 |
| `installAllowed` | 이 레이어 패키지의 스토어 설치 · 갱신 허용 | 열림 | **관리자 MFA**(`osc-otp-confirm`) + 사유 |

- `installAllowed`가 닫히면 그 레이어 패키지의 **설치 · 갱신 계획**을 만들 때 거절한다(409 `osr_layer_closed`).
  - 활성화 트랜잭션에서도 한 번 더 검사한다. 메뉴 경로 충돌 검사와 같은 자리다.
  - 내리기 계획과 인스턴스 동작은 막지 않는다.
- 레이어는 디스크립터의 `plane`(없으면 클래스)으로 정한다. D-89 §4.1과 같은 규칙이다.

### 5.2 원장

- 서비스 DB에 `osr.layer_settings`를 둔다. 열은 layer(키), settings(jsonb, 닫힌 형식), revision, updated_by, updated_at, reason이다.
- 바뀔 때마다 이전 값과 새 값을 이력 표(또는 기존 감사 표)에 남긴다.
- 쓰기는 정해진 함수 하나로만 한다. `osr_runtime`에 그 함수 실행 권한만 준다.
- 행이 없으면 기본값이다. 이행 파일은 새 번호(023 이후)로 낸다. 운영 반영 때 적용 표시(`installation.migrations`)를 함께 남긴다.

### 5.3 서버

- `GET /console-api/osr/layers/<layer>/settings`
- `POST /console-api/osr/layers/<layer>/settings`: 변경 + 판 + 사유
  - `installAllowed` 변경은 MFA 코드가 맞아야 반영한다.
  - 판이 다르면 409를 돌려준다.
- `GET /console-api/navigation`이 레이어 옵션을 함께 돌려준다. 레일 표시 · 아이콘 · 메뉴 순서 · 숨김이 들어간다.

## 6. Carbon 아이콘 선택

- **참고할 구 버전:** 보관본 OpenSphere Console(Angular, `@carbon/icons` 11.82.0)의 확장 관리 화면에 있는 "메뉴 아이콘" 선택. 로컬 `/Volumes/DevOps/Projects/OpenSphere-Archive/OpenSphere-console`이다.
  - 선택 화면: `apps/console-web/src/app/pages/admin-plugins.ts`(검색 · 최대 300개 표시 · "∅" 기본값)
  - 아이콘 목록: `apps/console-web/src/app/os/icon-library.service.ts`. `@carbon/icons/metadata.json`을 지연 로딩하고, 빌드가 실제로 만든 목록과 대조한다.
  - 그리기: `os/os-raw-icon.ts`(선택 화면), `os/os-nav-icon.ts`(메뉴. 저장된 이름 → `assets/carbon-icons/<이름>.svg` → 없으면 기본)
  - 빌드 단계: `scripts/generate-carbon-icon-assets.mjs`와 시험 `scripts/carbon-icon-assets.test.mjs`. 정적 SVG와 `catalog.json`을 만들고, 2500개 미만이면 빌드를 멈춘다.
  - 저장 형식: 케밥 표기 아이콘 이름(`^[a-z0-9][a-z0-9-]{0,95}$`), 빈 값은 기본이다.
  - 이 방식을 따른다. 선택은 원장의 레이어 옵션(`icon`)에 저장한다(§5).
- **아이콘은 Console 빌드에 넣은 정해진 목록에서만 고른다.**
  - 외부 URL · 업로드 · 인라인 SVG는 받지 않는다.
  - 저장 값은 아이콘 이름(문자열)이다.
  - 목록에 없는 이름이면 레이어 기본 아이콘을 쓴다.
- 선택 화면에는 검색과 미리보기를 둔다. 고른 아이콘은 레일 · 섹션 홈 · 레이어 목록에 같이 쓴다.
- **빌드 검사:** 레이어 기본 아이콘과 고를 수 있는 아이콘 전부가 빌드 결과물에 실리는지 시험으로 확인한다. 이번 같은 404를 막는다.

## 7. 구현 단위와 합격 기준

구현은 Codex가 한다. 검수(합격 기준 대조) · 병합 · 운영 반영은 Claude가 한다. 단위마다 Gitea PR을 하나씩 내되, **앞 단위가 main에 병합된 뒤 main을 기준으로** 연다.

| 단위 | 범위 | 합격 기준 |
|---|---|---|
| **LM1 현황 + 아이콘 복구** | §4 화면 · 서버. 레이어 기본 아이콘을 빌드에 넣는다(Governance · Workspace · 대체 아이콘). 빌드 검사 시험 | 레이어 목록 · 세부가 원장 값을 보인다. 못 읽으면 "읽지 못함"이다. 레일의 네 아이콘과 섹션 홈 대체 아이콘이 빌드 결과물에 있다(시험). 새 원장 표가 없다 |
| **LM2 옵션** | §5. 원장 표 · 함수, 설정 API, 계획 · 활성화 단계의 `installAllowed` 검사, 셸의 레일 표시 · 메뉴 순서 · 숨김 반영 | 닫힌 레이어의 설치 · 갱신 계획은 409, 내리기는 허용. `installAllowed` 변경은 MFA 없이 거절. 판이 다르면 409. 바뀐 값은 이력에 남는다. 레일 숨김이 Console 재빌드 없이 반영된다. 격리 DB에서 이행을 리허설한다 |
| **LM3 아이콘 선택** | §6. Carbon 아이콘 목록(빌드에 포함), 검색 · 미리보기 선택 화면, `icon` 옵션 저장 · 반영 | 목록 밖 이름은 기본 아이콘으로 그린다. 고른 아이콘이 레일 · 섹션 홈 · 레이어 목록에 같이 보인다. 고를 수 있는 아이콘 전부가 빌드에 있다(시험) |
