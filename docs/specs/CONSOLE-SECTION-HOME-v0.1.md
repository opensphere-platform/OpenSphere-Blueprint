## 1. 문제 두 가지

1. **섹션 홈이 화면 규칙을 지키지 않는다.**
   - D-89에서 `#/fabric/overview`를 섹션 홈으로 바꾸면서 템플릿의 Fabric 대시보드 대신 설정 화면용 단순 목록 레이아웃을 썼다.
   - 그래서 다른 Fabric 화면(공통 페이지 틀 · 이동 경로 · 타일 · 표)과 맞지 않는다.
   - 사양(D-89 §3.1)이 내용만 정하고 레이아웃 기준을 정하지 않은 탓이다.
   - `#/fabric/shared/overview`(공유 서비스 묶음 개요)는 호스트 예약 주소인데, 아직 예시 데이터를 보여 주는 "(예시)" 화면이다.
2. **레이어 상태가 이미 해결된 과거 실패를 지금 문제처럼 보인다.**
   - D-90 1단계의 판정은 최근 계획 20건 가운데 거절 · 실패가 하나라도 있으면 "확인 필요"다.
   - 2026-11-23 운영에서 Fabric이 "확인 필요"였다. OpenSearch(11-22) · Samba AD(11-21)의 거절 두 건 때문인데, 둘 다 같은 판이 나중에 활성화됐다.
   - 승인만 되고 실행되지 않은 채 더 새 판으로 대체된 계획(RustFS 11-22 13:35)도 "승인됨"처럼 남는다.

## 2. 화면 기준(D-89 개정)

### 2.1 공통 틀

섹션 홈과 묶음 개요는 템플릿 Fabric 화면과 **같은 틀**을 쓴다.

| 요소 | 기준 | 템플릿 참고 |
|---|---|---|
| 페이지 틀 | 공통 페이지 틀(제목 · 설명 · 이동 경로 자리) | `console/dummy/src/app/features/containers/` 의 page frame, `fabric.component.ts` |
| 이동 경로 | `<섹션 이름>` / `<묶음 이름>` | `fabric.component.ts`의 `page-breadcrumb` |
| 묶음 타일 | 호스트 묶음마다 클릭 타일 하나(설치 수 · 한 줄 설명) | `.groups` · `cds-clickable-tile.group-tile` |
| 대시보드 격자 | 타일 셋: 인벤토리 · 확인할 것 · 바로가기 | `.dashboard-grid` · `cds-tile.inventory` · `cds-tile.resume` |
| 표 | Carbon 표 | `.table-block` · `cds-table` |
| 스타일 | 템플릿 CSS를 재사용한다. 설정 화면용 `app-toolbar` · `app-table` 레이아웃을 섹션 화면에 쓰지 않는다 | `containers.component.css` · `fabric.component.css` |

- **값은 모두 원장 · 스토어 · 메뉴 조회의 실제 값이다.** 예시 문구와 "예시 화면" 알림을 쓰지 않는다.
- 읽지 못한 값은 "읽지 못함"으로 쓴다. 빈 것과 읽지 못한 것을 구분한다.
- 제품명 앞에 로고를 둔다. 화면 문구는 한국어로 쓴다.
- 좁은 화면에서는 타일이 한 줄씩 내려온다(템플릿과 같은 격자 규칙).

### 2.2 섹션 홈(`#/<section>`, `#/<section>/overview`)

| 영역 | 내용 |
|---|---|
| 머리 | 레이어 이름(레이어 아이콘), 한 줄 정의, "스토어에서 받기", "레이어 관리"(관리자) |
| 묶음 타일 | D-89 §4.2의 호스트 묶음마다 설치 수. 클릭하면 그 묶음 개요(Fabric `shared`) 또는 그 묶음의 첫 메뉴로 간다. 빈 묶음은 "설치된 기능 없음" |
| 인벤토리 | 설치된 패키지 · 갱신 가능 · 인스턴스(있는 레이어) · 앱 연결(있는 레이어) |
| 확인할 것 | §3 판정의 "지금 확인할 것" 항목(모듈 · 사유 · 링크). 없으면 "확인할 것이 없습니다" |
| 바로가기 | 설치된 메뉴 항목(로고 + 이름), 레이어 관리, 이 레이어로 거른 스토어 |
| (HISS만) | 위로 넘기는 것(인도 지점 다섯), 변경 · 이력. 지금 섹션 홈에 있는 내용을 이 틀로 옮긴다 |

- 패키지가 하나도 없는 레이어는 묶음 타일이 모두 "설치된 기능 없음"이다. 인벤토리는 0, 바로가기는 스토어 · 레이어 관리뿐이다.

### 2.3 Fabric 공유 서비스 개요(`#/fabric/shared/overview`)

- 예시 화면을 실제 화면으로 바꾼다. 호스트 예약 주소는 그대로 쓴다.
- 템플릿의 Provider 카드 틀(`fabric-providers.component.ts`)에 **설치된 공유 서비스**를 넣는다.
  - 카드 내용: 로고 · 이름 · 설치된 판 · 상태 · 인스턴스 수 · 앱 연결 수 · 그 화면으로 가는 링크
- 설치되지 않은 공유 서비스는 카드로 그리지 않는다. 대신 "스토어에서 더 받기" 카드 하나를 둔다.
- 이 화면은 보조 탐색의 "공유 서비스" 묶음 맨 위에 "개요"로 들어간다. 템플릿 예시 묶음의 "개요 · Provider" 항목은 뺀다.
- `#/fabric/shared/instances` · `bindings`(전체 인스턴스 · 연결)는 이번 범위가 아니다. 예시로 남긴다.

## 3. 레이어 상태 판정(D-90 개정)

### 3.1 지금 상태는 모듈마다 가장 최근의 것으로 정한다

| 판정 | 조건 |
|---|---|
| **확인 필요** | 아래 중 하나 |
| | · 보류된 확장 선언(`withheld`) |
| | · `unknown` 인스턴스 |
| | · 채널 후보의 메뉴 주소 충돌 |
| | · 모듈의 **가장 최근** 설치 · 내리기 계획 결과가 거절 · 실패 · 미확정이고, 그 뒤에 그 모듈의 성공한 활성화 · 내리기가 없다 |
| | · 실행부가 시작했는데 결과가 기록되지 않은 계획(진행 중이 아닌 것) |
| **읽지 못함** | 판정에 필요한 원천 하나라도 읽지 못함 |
| **정상** | 그 밖 |

### 3.2 지나간 것은 이력에만 보인다

- **해소된 실패:** 나중에 같은 모듈이 성공한 거절 · 실패 계획은 "해소됨"으로 표시한다. 레이어 세부의 변경 이력에만 보이고 상태에는 반영하지 않는다.
- **대체된 승인:** 승인됐지만 실행되지 않았고, 이후 그 모듈의 다른 계획이 활성화된 계획은 "대체됨"으로 표시한다. 이것도 상태에 반영하지 않는다.
  - 대체된 계획은 fence가 맞지 않아 적용될 수 없다. 이를 근거와 함께 보인다.
- 섹션 홈의 "확인할 것"과 레이어 목록의 상태는 같은 판정을 쓴다.

구현은 Codex가 한다. 검수(합격 기준 대조, 빌드 결과물 확인) · 병합 · 운영 반영은 Claude가 한다. 단위마다 Gitea PR을 하나씩 내되, 앞 단위가 main에 병합된 뒤 main을 기준으로 연다.

| 단위 | 범위 | 합격 기준 |
|---|---|---|
| **SH1 상태 판정** | §3. 서버 판정 · 세부 화면의 이력 표시(해소됨 · 대체됨) | 2026-11-23 운영과 같은 원장(거절 뒤 같은 판 활성화, 대체된 승인 계획)을 시험 사례로 두고, Fabric이 "정상"이 되는 것을 확인한다. 마지막 계획이 거절이면 "확인 필요". 원천 하나를 못 읽으면 "읽지 못함". Rust 단위 시험 포함 |
| **SH2 섹션 홈 틀** | §2.1 · §2.2. 네 섹션 홈을 템플릿 틀로 다시 그림 | 네 섹션 모두 공통 페이지 틀 · 이동 경로 · 묶음 타일 · 대시보드 격자를 쓴다. 설정 화면용 레이아웃 클래스를 쓰지 않는다. 값은 실제 원장 값이다. 패키지 없는 레이어의 빈 상태, 읽기 실패를 구분한다. 1440 · 390 px 화면 캡처를 PR에 남긴다 |
