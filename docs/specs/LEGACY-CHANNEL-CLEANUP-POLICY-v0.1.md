# 예전 채널 정리 방침 v0.1 — S5

**상태:** 스토어 기본 구성 완료 기준 S5의 산출물. Claude가 D-113 · D-118의 실행 방침으로 정한다. 운영 변경(2단계)은 반영 때마다 소유자 승인을 받는다.
**근거:** Backbone `docs/osr/LEGACY-CHANNEL-REMOVAL.md`(PR 293, Codex 작성, 운영 읽기 전용 확인 2026-11-28).
**관련:** D-113(예전 채널을 닫는다, 되살리지 않는다), D-118(예전 설치본을 모두 내리고 스토어로 다시 구성), [검증 추적 대장](VERIFICATION-TRACEABILITY-LEDGER-v0.1.md).

## 1. 지금의 상태(2026-11-28)

- 예전 채널로 설치된 것: 6개 모두 `stopped`. 활성 화면 0, 열린 예약 0, 미결 승인 0.
- 새 예전 채널 설치 계획은 서버가 410으로 거절한다(PR 285). 스토어 화면에는 예전 채널 줄이 없다.
- **아직 돌고 있는 것:** 예전 GHCR 전역 reader(`backbone-registry-reader`). 읽기 토큰이 폐기돼 403만 낸다. 경계 정책 · Console 패치 · 자격 참조가 함께 남아 있다.
- 예전 v1 목록 발행 · 모듈 번들 발행 워크플로, 직접 등록 · 계획 · 인스턴스 · Shell 쓰기 분기, `/ui/<module>/` 서빙, `EXTENSION_COMPAT`이 코드에 남아 있다.

## 2. 원칙

1. **이력은 지우지 않는다.** 원장(설치 · 인스턴스 · Claim · 계획 · 이벤트 · 예약 · 감사), Core 승인 · MFA 사용 기록, 릴리스 · 서명 · 판정 · 철회 기록, 이전 채널 목록과 정적 아카이브는 원래 좌표 그대로 남긴다. `unknown`을 완료나 취소로 덮지 않는다. `inst-<module>` 문자열은 감사 식별자로 남긴다.
2. **공용 경로는 예전 채널이 아니다.** 계획 검토 · 확인 · 적용 · 진행, Core 계획 API, 실행부 입구, 예약 · fence, 스토어 범위 reader, Setup의 제품 채널 · 이미지 공급망은 이름에 `plans` · `channel` · `registry`가 있어도 남긴다.
3. **입구부터 닫고, 실행 분기는 나중에 좁힌다.** 수집 · 발행 → 생성 · 실행 입구 → 화면 주소 → 죽은 분기 순서다. 각 단계에서 삭제 대상의 호출자가 0개인지 소스와 운영 읽기로 확인한다.
4. **되살리지 않는다.** 예전 reader의 읽기 토큰, 예전 목록 발행 토큰은 복구하지 않는다(D-113). 이미지를 되돌려도 D-118의 신규 설치 거절은 유지한다.
5. **구판 클라이언트에는 명시적인 종료 응답을 준다.** 410과 스토어 주소 안내를 남긴다. 조용히 다른 패키지로 넘기지 않는다.

## 3. 단계와 시점

| 단계 | 내용 | 여는 조건 | 운영 승인 | 대장 |
|---|---|---|---|---|
| 1 | 닫힌 상태 · 증거 고정: 변경 직전에 활성 설치 · 화면 · 예약 · 미완료 실행 · `cleanup_pending`을 다시 읽고, 과거 `unknown` 2건의 영수증과 대상 관계를 기록 | 지금 | — | V-61 |
| 2 | 예전 GHCR reader의 Deployment · 경계 정책 · Console 패치 · 자격 참조 정리, 예전 v1 목록 발행 · 모듈 번들 발행 워크플로 종료. 레포 reader와 공용 객체 틀을 먼저 분리 | 1단계 뒤. 다음 운영 반영(A-19)에 묶는다 | 필요 | V-62 |
| 3 | 예전 직접 등록 · 계획 · 인스턴스 · Shell 쓰기 분기 종료(410 유지), 구판 CLI 안내. Core · Services의 예전 실행 분기는 격리 원장으로 읽기 · 감사 · 복구를 확인한 뒤 좁힌다 | S2(신원 패키지 운영 설치) 뒤 | 이미지 반영 때 | V-63 |
| 4 | `/ui/<module>/` · 짧은 주소 · `EXTENSION_COMPAT` 종료 | 더미 화면을 스토어 주소(`/ui/pkg/…`)로 운영 설치 · 열기 · 회수까지 확인한 뒤, 공급자별 Fabric 화면이 패키지로 갖춰진 뒤 | 이미지 반영 때 | V-64 |
| 5 | 죽은 분기 · 시험 정리. 새 이행이 필요하면 기존 판이 그 이행 위에서 스토어 설치본을 읽고 정지할 수 있는지 먼저 증명 | 3 · 4 뒤 | 이행이 있으면 필요 | V-65 |

S5 완료 기준은 "방침이 정해진다"이며 이 문서로 닫는다. 단계 2~5의 실행은 위 시점에 대장에서 추적한다. 2단계는 스토어 기본 구성 안(다음 운영 반영)에서 한다.

## 4. 결정하지 않은 것

- 보존 기록의 보존 기간과 읽기 전용 보관 위치. 지금은 원장 안에 그대로 둔다.
- 다른 등록 스토어용 format 1(예전 수용 코드를 쓰는 `scoped_legacy`)의 폐기 여부. 지금 format 1 스토어는 0개다. 폐기하면 검증 벡터를 남긴다.
