## 2. `ui` 정적 화면 모듈 (D6)

실행하지 않는 모듈이다. 워크로드 · 서비스 · 저장 claim · RBAC이 없다.

### 2.1 번들

| layer | 형식 | 내용 |
|---|---|---|
| `descriptor` · `manual` · `commands` · `knowledge` | canonical JSON | 다른 클래스와 같다 |
| `static-index` | canonical JSON | 파일마다 경로 · sha256 · 크기 · 유형, 그리고 `static` layer의 digest와 크기 |
| `static` | 압축하지 않은 tar | 화면 파일. 경로순, 일반 파일만, mtime 0 |

- 디스크립터는 `runtime` · `storage`를 선언할 수 없다. `ui` 선언(`entry`, `access`, `navigation`)과 `profile: ui.console-static`이 필수다.
- 생명주기는 OSR 고정 명령 `osr.ui.install` · `update` · `rollback` · `retire`다. 모듈이 자기 명령으로 바꿀 수 없다.
- 명령 계약의 `ownerBinding`은 `osr.ui-host`(Console)이고, 표준 명령은 `status` · `inspect` · `verify`다. 상태를 바꾸는 effect는 정책과 profile이 막는다.
- JSON이 아닌 layer는 `ui`의 `static` 하나만 허용한다.

### 2.2 판정

- **등록 때:** `static` layer의 바이트는 보지 않는다. 서명된 manifest의 digest와 크기로만 묶인다. `static-index`가 그 layer를 가리키고 진입 파일을 포함하는지 본다. 어긋나면 `UiStaticInvalid`(7단계).
- **파일을 받을 때:** 서버는 묶음을 통째로 받지 않는다. 파일을 하나씩 받아 `static-index`의 경로 · 크기 · sha256과 대조한다. 다 받으면 저장된 파일로 묶음을 같은 규칙으로 다시 만들어 digest를 계산하고, 서명된 `static` layer와 같을 때만 마감한다.
- **로그인 없이 보이는 화면:** `access: public`은 선언만으로 되지 않는다. capability `console.ui.public`을 요청해야 하고 정책과 profile이 둘 다 허용해야 한다.

### 2.3 서빙

- Console이 `/ui/<module-id>/`에서 그 모듈에 **지금 적용 중인 번들**의 파일만 내려준다.
- 요청마다 적용 상태를 확인한다. 회수하거나 중지하면 즉시 멈춘다.
- 화면 파일은 Console의 보안 정책(CSP)을 그대로 받는다. 서버 권한을 얻지 않는다.

| 항목 | 구분 |
|---|---|
| 화면 파일을 services DB에 번들 digest별 불변 행으로 둔다 | 구현 선택 |
| 화면 묶음을 압축하지 않은 tar로 한다(서버에 새 의존성이 없다) | 구현 선택 |
| 탐색 메뉴는 디스크립터 `ui.navigation`에서 오고, 적용 중인 모듈만 보인다 | 구현 선택 |

## 3. 승인과 적용의 연결 (D2)

| 단계 | 어디서 | 하는 일 |
|---|---|---|
| 계획 | OSR → Core | OSR이 설치 계획(`opensphere.osr-install-plan/v1`)을 만들고, Core가 직접 다시 계산한 canonical digest로 기록한다 |
| 승인 | Core | 독립 승인 범위 `osr`. 검토자가 등록된 키로 서명한다. 계획을 만든 사람은 승인할 수 없다 |
| 적용 | OSR | Core에서 유효한 승인을 다시 읽고, 현재 상태로 계획을 다시 만들어 계약의 실행 판정으로 대조한 뒤, 원장이 fence · 회수 · 판정 · 파일 상태를 확인하고 적용한다 |

- Core는 이 범위에서 효과를 내지 않는다. 계획과 승인을 기록하고 승인이 유효한지 알려 줄 뿐이다.
- 승인은 짧은 시간(최대 300초)만 유효하고 한 번만 쓰인다. 적용을 거절하면 새 계획과 새 승인이 필요하다.
- 응답이 끊기면 기록된 상태를 읽어 이어 간다. 두 번 적용하지 않는다.
- 지금은 `ui` 클래스만 이 경로로 설치한다. `provider` · `assembly`는 제한 실행부가 생긴 뒤다.

## 4. 게시 (D4)

| 하는 일 | 누가 |
|---|---|
| 번들 빌드, 레지스트리 push, SBOM · 출처 발급 | CI(보호된 main) |
| 릴리스 서명 | 운영자 |
| 서명을 레지스트리에 붙이기 | CI. 저장소에 병합된 공개 키로 서명을 먼저 확인한다 |
| 검증 맥락 snapshot 서명 | 신뢰 운영자 |

- 번들은 재현된다. 첫 화면 모듈은 CI가 올린 번들과 다른 기계에서 다시 만든 번들이 바이트까지 같았다.
- 서명 · SBOM · 출처는 번들을 subject로 하는 referrer다. 레지스트리에 referrers API가 없으면 tag 방식 목록을 쓴다.
