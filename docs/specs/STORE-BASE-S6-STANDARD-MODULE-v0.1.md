# S6 — OpenSphere 표준 모듈 적격(패키지 적격 · 공급망 신뢰) v0.1

**상태:** 소유자 확정(2026-11-28: "S6으로 넣기"). 스토어 기본 구성의 완료 기준 S6이다. [검증 추적 대장](VERIFICATION-TRACEABILITY-LEDGER-v0.1.md)의 등급 A(패키지 적격) · B(공급망 신뢰)를 묶는다.
**작성:** Claude. 구현은 Codex(판정기 · 패키지 · 시험)와 Claude(게시 경로 · 운영 반영)가 나눈다.
**순서상의 자리:** 스토어 기본 구성(S1~S6)을 마친 다음 AI 에이전트 전략(D-119)을 구현한다.

## 1. 완료의 뜻

**운영에 게시되는 모든 스토어 패키지가 OS 통합 계약 v1.1에 맞는 판이고, 그것을 판정기가 거절로 강제하며, 게시 단계가 이미지의 내용물 · 취약점 · 라이선스를 증거로 남긴다.**

대상 패키지: Valkey · RustFS · OpenSearch · PostgreSQL · Samba AD · Keycloak · 더미 화면(일곱).

## 2. 등급 A — 패키지 적격

| 항목 | 대장 | 판정기가 할 일(Node · Rust · Setup 봉인 사본 · 공유 사례) | 패키지가 할 일 |
|---|---|---|---|
| A1 이벤트 선언 | V-01 | `events` part(`opensphere.package-events/v1`, 계약 §10.4)의 스키마 · 정규 바이트 · 거절 사유. 자리표시자 · 길이 · 개수 한도 | 일곱 모두 `events` part를 낸다(화면 패키지는 빈 목록이 아니라 해당 없음을 판정기가 받는 형태로). 최소: 준비 안 됨(`instance.notReady`)과 시작 실패(`startup.problem`) |
| A2 로그 형식 | V-02 | `logFormat`(`json` · `text`, json이면 필드 이름) 검증 | 실행 워크로드가 있는 패키지는 `logFormat`을 낸다 |
| A3 문제 코드 사전 | V-35 | 문제 코드 part(에이전트 운용 M3)의 스키마: 코드 · 범위 · 근거 · 확인할 읽기 명령(선언된 Shell 명령 id) · 제안 행동 | 실행 워크로드가 있는 패키지는 호스트가 내는 시작 실패 코드(`image-pull-auth` · `crash-loop` 등)에 대응하는 항목을 낸다 |
| A4 모르는 part 거절 | V-03 | 계약이 정한 part 이름만 받는다. 모르는 이름은 거절 | — |
| A5 listing 필수 | V-05 | listing 없는 패키지 거절(품질 표준 G-4) | Sb · Kc listing 추가 |
| A6 Fabric 화면 필수 | V-06 | 인스턴스를 만드는 공급자 패키지는 서비스 화면과 인스턴스 세부를 내야 한다. 세부 탭은 호스트 계약이 정한 기준 집합(13개)을 따른다 | Pg · Sb · Kc 화면(PR 286~288), 값은 H1 |
| A7 판 올림 자격 회수 선언 | V-08 | Claim을 발급하는 공급자 패키지는 `releaseCompatibility`를 내야 한다 | Vk(조건부 → 기본) · Pg · Sb · Kc |
| A8 로그에 자격 없음 | V-09 | — | 격리 시험: 발급 · 회수 동안 엔진 · Job의 stdout · stderr에 자격 값이 없다(고정 시험 문자열로 확인). 패키지 시험의 일부 |
| A9 모듈 명세 x.12 | V-15 | — | 설계(Claude): PostgreSQL · OpenSearch · RustFS · Samba AD · Keycloak의 알림 · 로그 절을 모듈 명세에 더한다. 패키지 선언은 그 절을 따른다 |

**판정기 변경의 원칙:** 추가만 한다. 이미 게시된 판은 그대로 읽히되, 새 판의 게시와 새 설치 계획은 새 규칙을 통과해야 한다(이미 설치된 것의 동작은 바뀌지 않는다). 이전 코드에서 실패하는 사례를 공유 사례에 넣는다.

## 3. 등급 B — 공급망 신뢰

| 항목 | 대장 | 할 일 | 맡는 곳 |
|---|---|---|---|
| B1 실제 SBOM | V-42 | 이미지 발행 때 이미지 안의 구성요소 목록(SPDX 또는 CycloneDX)을 만들어 보관하고, 패키지의 SBOM 문장이 그 digest를 가리킨다 | 발행 파이프라인(`publish-images.yaml`) + 패키지 조립 |
| B2 취약점 검사 | V-44 | 패키지가 쓰는 모든 이미지(엔진 · Claim Job)를 검사한다. 수정 가능하고 영향이 확인된 Critical은 게시 차단, High는 30일 기한의 기록. 예외는 사유 · 만료가 있는 서명된 기록으로만 | 발행 파이프라인 + 기본 스토어 게시 단계 |
| B3 라이선스 허용 목록 | V-43 | 패키지 descriptor의 라이선스와 이미지 구성요소의 라이선스를 허용 목록과 대조. 목록 밖은 게시 차단 또는 기록된 예외 | 기본 스토어 게시 단계 |
| B4 빌드 증명 대조 | V-41 | 공급자 등록부의 빌더 정책과 실제 provenance(저장소 · 커밋 · 워크플로)를 대조한다. 자기 선언만으로는 통과하지 않는다 | 판정기 + 게시 단계 |
| B5 품질 등급 | V-45 | 게시 단계가 B1~B4 결과로 등급(검증됨)을 계산해 서명 목록에 싣고, 호스트는 서명된 값만 표시한다. 설치본 최소 등급 집행은 B1~B4가 운영에 들어간 뒤 켠다 | 게시 단계 + 호스트 |

**도구:** 이미 쓰는 것을 넓힌다. OpenSearch 이미지에 쓰는 Trivy(판 고정 · 해시 검증) 경로를 모든 이미지로 넓히고, SBOM도 같은 도구 또는 판을 고정한 도구 하나로 만든다. 새 외부 서비스에 이미지를 보내지 않는다.

### 3.1 등급 B의 게시 경로 설계(Claude, 2026-11-28)

| 단계 | 하는 일 | 증거 | 실패 시 |
|---|---|---|---|
| ① 이미지 발행(`publish-images.yaml`, 보호된 main · 운영 RKE2 러너) | 빌드한 OCI마다 판 · 해시를 고정한 Trivy로 SBOM(SPDX JSON)과 취약점 보고서를 만든다. OpenSearch 경로(`publish-opensearch-runtime.sh`)의 방식을 모든 구성요소로 넓힌다 | SBOM · 보고서를 발행 원장 행에 digest로 남기고, OCI 보관본 옆에 같이 보관한다. GHCR에는 이미지의 referrer로 붙인다 | 수정 가능한 Critical → 발행 중단. High → 30일 기한 기록 |
| ② 예외 | 취약점 · 라이선스 예외는 저장소의 검토된 파일(보호 main · PR 승인)에만 둔다. 항목마다 대상 digest · 사유 · 만료 | 예외 파일 digest를 보고서에 싣는다 | 만료된 예외는 없는 것으로 본다 |
| ③ 패키지 조립 | 패키지의 SBOM 문장이 이미지 SBOM digest들을 가리킨다(지금의 이름 · 판 목록 대신). 출처(provenance)는 자기 선언이 아니라 **발행 원장 행**(실행 id · 원천 커밋 · 워크플로 경로)에서 만든다 | 번들의 SBOM · 출처 | 원장 행이 없으면 조립 거절 |
| ④ 기본 스토어 게시(`build.mjs`, Claude) | descriptor 라이선스와 SBOM 구성요소 라이선스를 허용 목록과 대조, 출처를 공급자 등록부의 빌더 정책과 대조, 결과로 등급 "검증됨"을 계산해 서명 목록에 싣는다 | 서명 목록의 `quality` | 목록 밖 라이선스 · 정책과 다른 출처 → 게시 거절 |
| ⑤ 호스트 | 서명된 등급만 표시. 설치본 최소 등급 집행은 ①~④가 운영에 들어간 뒤 켠다 | 스토어 화면 | — |

**빌더 정책의 기준:** 기본 스토어의 빌더는 Gitea 보호 main과 운영 RKE2 러너다(소유자 결정 2026-11-19: CI는 운영 RKE2). 품질 표준의 "셀프 호스티드 러너 금지"는 Universe(GitHub 호스티드 빌드)의 규칙이다. 기본 스토어는 빌더 정책 종류 `gitea-protected-main`에 저장소 · ref · 워크플로 경로 · 러너 식별을 고정하고, 출처가 그것과 정확히 같아야 통과한다. 이 차이는 공급자 등록부에 명시한다.

**맡는 곳:** ① · ② · ③과 판정기의 출처 대조(B4)는 Codex PR, ④는 Claude(`.runtime/default-store-20261127/build.mjs`와 그 정본 이전), ⑤는 Codex PR.

## 4. 완료 판정

- 일곱 패키지의 새 판이 기본 스토어에 게시되고 운영 reader가 받는다.
- 새 판정기를 실은 이미지가 운영에 반영 · 채택된다.
- 각 패키지에 대해 대장의 V-01 · V-02 · V-03 · V-05 · V-06 · V-08 · V-09 · V-15 · V-35 · V-41~V-45 칸이 ✅ 또는 기록된 예외다.
- 음성 시험: 선언이 빠진 패키지 · 모르는 part · listing 없는 패키지 · 화면 없는 공급자 · 수정 가능한 Critical이 있는 이미지 · 빌더 정책과 다른 provenance가 각각 거절된다.

## 5. 범위 밖(대장의 다른 등급)

이벤트의 호스트 발행 · 알림 전달(C9b · C9c), 로그 수집 · 열람(C10a · C10b), 재빌드 0회 대조, HISS 스토어화는 등급 C다. S6은 **선언과 그 강제**까지다. 선언을 받아 실제로 알리고 수집하는 쪽은 AI 에이전트 전략 구현과 나란히 순서를 정한다.
