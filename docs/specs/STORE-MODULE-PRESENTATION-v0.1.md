## 1. 원칙

1. **재빌드 0회는 그대로.** 스토어 추가, 스토어 소개 변경, 패키지 소개 변경, 새 패키지 화면은 모두 서명된 데이터다. Backbone 갱신이 필요한 것은 **카탈로그 판을 올릴 때뿐**이고, 그것도 묶어서 드물게(§4.2). 이 문서를 가능하게 하는 Backbone 변경은 한 번이다.
2. **중립은 지킨다.** 스토어 · 패키지의 공통 부분에는 **제품을 모르는 표시 정보**(글 · 그림 · 링크 · 묶음)만 둔다. A2UI 화면은 **OpenSphere 제품 부분**에만 둔다. 다른 제품은 중립 정보로 자기 화면을 그리고, OpenSphere 화면이 없거나 못 그리면 OpenSphere도 중립 정보로 그린다(대체 표시).
3. **소개는 주장, 사실은 호스트.** 스토어 · 공급자 · 패키지가 내는 소개는 **"자기 소개"로 표시한 구역**에만 그린다. 신뢰 · 서명 · digest · 품질 등급 · 권한 · 자원 · 의존 · 설치 상태 같은 사실은 지금처럼 호스트가 계산해 OS 틀로 그린다. 소개 화면은 사실처럼 보이는 표시(신뢰 배지 · 상태 색 · 승인 단추 흉내)를 직접 만들 수 없다 — 그런 컴포넌트는 호스트 원천에만 바인딩된다(§4.4).
4. **보안 상호작용은 OS.** 연결 승인 · 지문 대조 · 범위 · MFA · 설치 승인은 D-97 ③ 그대로 OS가 그린다. 소개 화면은 그 창 안에 들어가지 않는다.
5. **서명에 묶인다.** 소개 문서는 그 스토어(또는 공급자) 서명에 묶이고, 같은 검증 스냅숏으로 활성화된다(다중 스토어 §5 "한 묶음으로 활성화"). 서명을 검증하지 못한 문서는 그리지 않는다.
6. **닫힌 데이터, 닫힌 동작.** A2UI 소개 화면의 데이터 모델은 호스트가 채운 닫힌 원천만 쓴다(§3). 설치 전 화면에는 Shell 명령이 없고, 동작은 정확한 OS 주소로 가는 `navigate`뿐이다.

## 2. 스토어의 자기 소개

### 2.1 스토어 프로필(중립) `store.profile/v1`

| 필드 | 내용 | 한도 |
|---|---|---|
| `displayName` | 스토어 표시 이름(언어별) | 64자 |
| `summary` | 한 줄 소개(언어별) | 140자 |
| `description` | markdown(호스트 정리 규칙은 계약 §2와 같음) | 16KiB |
| `operator` | 운영 주체 이름 · https 주소 · 문의 주소 | — |
| `icon` · `banner` | `store.profile-media`의 파일 digest | 각 1MiB, webp · png · svg(정리) |
| `policies` | 심사 정책 · 보안 공지 · 개인정보 · 이용 조건 링크(https) | 8개 |
| `collections` | 이름 붙인 패키지 묶음(예: "추천", "회사 신원", "관측"): 제목 · 설명 · 패키지 정체 목록 | 묶음 16, 묶음당 64 |
| `locales` | 제공 언어, 기본 언어 | — |

- **서명과 판:** 채널 목록이 `profile: { digest }`를 담는다(지금 `publishers: { digest }`와 같은 방식). 그래서 프로필은 목록 · 등록부와 **같은 root · 스토어 정체 · 스냅숏**으로 함께 활성화되고, 롤백 · 동결 규칙도 같이 받는다. 미디어는 불투명 묶음 `store.profile-media` + 색인(지금 `listing-media`와 같은 형식).
- **공급자 소개:** 공급자 등록부의 공급자 항목에 중립 표시 정보(`displayName` · `summary` · https 주소 · 아이콘 digest)를 더한다. **스토어가 서명한 등록부에 있으므로 스토어가 그 이름을 보증한다.** 호스트는 이름 옆에 항상 정체(`공급자/…`)와 키 지문 일부를 같이 보인다(사칭 방지).
- **`collections`는 소개일 뿐이다.** 범위 · 설치 허용 · 순서 결정은 지금처럼 설치본 관리자 설정이 정한다. 묶음에 있는 패키지라도 범위 밖이면 "이 설치본에서 받지 않음"으로 보인다.

### 2.2 OpenSphere 제품 부분 `store.profile.opensphere/v1`

- A2UI surface 두 개(선택): `store.intro`(연결 전 · 후 소개), `store.home`(연결 후 스토어 개요의 소개 구역). 카탈로그는 §4 판 규칙대로.
- 데이터 원천: §3의 `store.*` · `package.card`만.
- 없거나 판정 실패면 §2.1 중립 정보로 OS 틀이 그린다.

### 2.3 장면

| 장면 | 보이는 것 |
|---|---|
| **연결 전 미리 보기**(MS4) | 소유자가 가져온 신뢰 변경 문서의 root로 목록 · 등록부 · 프로필 서명을 검증한 뒤, **"아직 신뢰하지 않은 스토어의 자기 소개"** 띠를 두른 구역에 프로필(또는 `store.intro`)을 보인다. 그 옆 OS 구역: root 지문 · 스토어 정체 · 채널 · 범위 · 공급자 수 · 패키지 수 · 유효 기간. 승인(MFA)은 지금처럼 Setup 소유자 터미널 |

| **스토어 둘러보기** | 묶음 · 공급자별 패키지 카드(호스트 원천 `package.card`), 카드에서 패키지 소개로 `navigate` |

## 3. 데이터 원천(설치 전 · 스토어 화면 전용, 새로)

모두 호스트가 검증된 서명 문서와 원장에서 만든다. 패키지 · 스토어가 값을 넣을 수 없다(정적 글자 제외).

| 원천 | 내용 | 쓰는 화면 |
|---|---|---|
| `store.identity` · `store.profile` | 스토어 정체 · root 지문 일부 · 검증된 프로필 | 스토어 화면 |
| `store.status` · `store.scope` | 동기 상태 · 범위 · 멈춤 | 연결 후 |
| `store.publishers` | 등록부의 공급자 표시 정보 · 정체 · 허용 클래스 | 스토어 화면 |
| `store.collections` | 묶음 + 각 항목의 `package.card` | 스토어 화면 |
| `package.card` | 정체 · 표시 이름 · 아이콘 · 요약 · 최신 판 · 품질 등급 · 이 설치본에서의 상태(설치됨 · 받지 않음 · 범위 밖) | 모든 소개 화면 |
| `package.listing` | 검증된 listing(요약 · 설명 · 스크린샷 · 링크 · 릴리스 노트) | 패키지 소개 |
| `package.facts` | 계약 §2의 호스트 계산 사실(레이어 · 원형 · 객체 kind · 한도 · 권한 · 저장 · 호환 판 · 서명자 · digest · 알림 · UI 모듈 원천) | 패키지 소개(읽기만, 표시는 OS 구역 우선) |
| `package.dependencies` | 의존 패키지의 `package.card` + 요구 판 범위 + 이 설치본에서 충족 여부 | 패키지 소개 |
| `package.supplies` | 이 패키지가 **공급하는** Claim 종류 · scheme · 공급 범위, **소비하는** 슬롯(종류 · 필수 여부), 어셈블리 정의면 구성원 | 패키지 소개(하위 모듈) |
| `package.versions` | 판 기록(판 · 날짜 · 릴리스 노트 요약) | 패키지 소개 |

## 4. 모듈의 자기 소개

### 4.1 패키지 소개 화면

- **중립:** `listing` v2 = 지금 v1 필드 + 언어별 글 + 스크린샷 설명 필수(접근성) + `highlights`(짧은 특징 3~6개, 글만). markdown 정리 규칙은 그대로.
- **OpenSphere 제품 부분:** 확장 선언에 화면 종류 `store.detail.intro`(A2UI surface 하나)를 연다. 스토어 상세 "개요" 탭의 **소개 구역**에 그린다. 탭 구조(개요 · 매뉴얼 · 권한과 자원 · 판 기록)와 OS 구역(사실 · 설치 단추)은 그대로다.
- **하위 모듈 소개:** `package.supplies` · `package.dependencies`로 "이 패키지가 내는 것 / 기대는 것"을 그린다. 다른 패키지는 `package.card`로만 보이고, 누르면 그 패키지 소개로 `navigate`. 다른 패키지의 소개 내용을 대신 쓰지 못한다.
- **설치 전에는 명령이 없다.** Button은 `navigate`만, CommandButton은 쓸 수 없다(판정기 거절).
- **판 선택:** 설치 전 소개는 **받으려는 판**의 화면을 쓴다. 설치 후 도움말 · 섹션 화면은 지금처럼 활성 판.

### 4.2 하위 모듈 표기 규칙

- 공급 관계는 실행 문서(`execution`의 Claim 발급 · 소비 선언)와 어셈블리 정의에서 **호스트가 뽑는다**. 패키지가 "우리는 X와 함께 쓴다" 같은 관계를 따로 주장하는 필드는 두지 않는다(주장과 사실이 갈라지는 것을 막음). 추천 조합은 스토어 `collections`의 몫이다.

## 5. A2UI 카탈로그 관리

### 5.1 판 체계

- **카탈로그 id는 주 판:** `opensphere.carbon/v1`. 그 안의 **개정 번호 `1.N`** 은 더하기만 한다(새 컴포넌트 · 새 선택 속성 · 새 원천). 지우거나 뜻을 바꾸면 `v2`.
- **패키지 선언:** 화면마다 `catalog: "opensphere.carbon/v1"` + `catalogRevision: ">=1.N"`(없으면 1.0).
- **호스트:** 지원하는 카탈로그 id와 최고 개정을 공개한다(Console API `GET /osr/catalogs`, CLI `os catalog`, SDK에 같은 목록).
- **호스트 개정이 낮을 때:**
  - 설치 전 소개 화면 → 그리지 않고 중립 정보로 대체 표시, "이 화면은 더 새 OpenSphere가 필요" 한 줄.
  - 설치 후 화면(메뉴 · 세부 탭) → **계획 단계에서 거절**(409, 이유 `osr_catalog_revision_unsupported`). 설치한 뒤 화면이 깨지는 일을 막는다.
- **판정:** 판정기 둘 · Setup 봉인 사본은 선언한 개정의 스키마로 판정하고, 선언보다 새 개정의 컴포넌트를 쓰면 거절한다.
- **v2가 생기면** 호스트는 v1과 v2를 함께 지원하는 기간을 둔다(§5.3).

### 5.2 확장 절차

1. **제안:** 공급자 · 우리 누구나. 실제로 그 컴포넌트를 쓸 패키지와 화면 초안이 있어야 받는다(D-97 "쓸 패키지가 생길 때").
2. **정의:** Claude가 계약에 컴포넌트 · 속성 · 바인딩 · 한도 · 금지를 적는다. Carbon 사용 규칙은 컴포넌트 안에 고정.
3. **구현:** Codex가 생성기 · 판정기 둘 · Setup 봉인 사본 · 렌더러 · 공유 사례 · 렌더러 적합성 시험을 한 PR로.
4. **승인 · 반영:** 소유자 승인, 개정 번호 하나 올림. **Backbone 정기 갱신에 묶어 싣는다**(카탈로그 확장 때문에 따로 재빌드하지 않는다).
5. **상류 기본 카탈로그 갱신**도 같은 절차(새 커밋 · sha256 고정, 생성기 `--check`로 제약 누락 검사).

### 5.3 폐지

- 컴포넌트 · 속성 폐지는 **예고 → 판정기 경고 → 다음 주 판에서 제거**. 예고 뒤 최소 두 번의 Backbone 정기 갱신 동안 유지.
- 주 판 v1 지원 종료는 그 판만 쓰는 활성 설치본이 남아 있으면 하지 않는다(원장으로 확인).

### 5.4 배포

- SDK `@triangles-store/store-sdk`에 개정별 카탈로그 생성본 · 원천 목록 · 공유 사례 · 미리 보기 렌더러(로컬, Q-6 범위)를 넣는다.
- 스토어 심사(MS7b 게시 도구)는 목록 항목의 `targets`(제품 · 계약 범위)와 화면의 카탈로그 개정이 맞는지 본다.
- 외부 공개(카탈로그 단독 배포)는 이번 범위가 아니다(D-97과 같음).

### 5.5 소개용 첫 확장 `1.1` 후보

| 컴포넌트 | 내용 | 막는 것 |
|---|---|---|
| **Image** | 같은 번들(또는 같은 스토어 프로필)의 `*-media` 파일 digest만 가리킴. 대체 글 필수, 크기 · 비율은 정해진 값 | URL · 다른 번들 미디어 · 추적 이미지 · 과대 파일 |
| **PackageCard** | `package.card` 원천에만 바인딩. 아이콘 → 이름 순서(제품명 앞 로고 규칙), 품질 · 상태는 호스트 색 | 패키지가 카드 내용을 직접 씀 |
| **LinkList** | https 글자 링크, 호스트가 도메인을 같이 보임, 새 창 | `javascript:` · 다른 scheme · 숨긴 주소 |
| **FeatureList** | 아이콘(번들된 Carbon 아이콘) + 짧은 글 목록 | 스타일 값 |
| **SupplyGraph** | `package.supplies` · `package.dependencies` 원천 전용, 공급 · 소비 관계를 Carbon 스타일로 | 임의 노드 · 관계 |

- 넣지 않는 것: Video · AudioPlayer · `openUrl` · 외부 iframe(그대로).
- 지금 `StatusTag` · `Notification`의 신뢰 · 상태 색을 소개 화면에서 쓰려면 호스트 원천 바인딩만 허용한다(§1 원칙 3). 정적 글자로 "검증됨" 등을 쓰는 것은 판정기가 막을 수 없으므로, 소개 구역 전체에 "자기 소개" 띠를 OS가 두른다.

## 6. 위협과 막는 방법

| 위협 | 막는 방법 |
|---|---|
| 소개 화면이 승인 · 신뢰 표시를 흉내 | 소개 구역 띠, 승인 창 밖에만 그림, 신뢰 색 컴포넌트는 호스트 원천 전용 |
| 다른 스토어 · 공급자 사칭 | 표시 이름 옆에 정체 · 지문 일부 고정 표시, 같은 표시 이름 경고 |
| 서명 없이 소개만 바꿈 | 프로필 digest가 채널 목록에, 같은 스냅숏 활성화 · 롤백 방지 |
| 외부 자원으로 추적 · 변조 | URL 이미지 없음, 미디어는 서명된 digest만, CSP 그대로 |
| 과대 문서 · 미디어로 화면 마비 | 계약 §6.3 한도 + 미디어 한도 + 블록 단위 "표시 한도 초과" |
| 연결 전 미리 보기가 신뢰를 유도 | "아직 신뢰하지 않은" 띠, 지문 대조는 OS 구역, 승인은 소유자 터미널 |
| 묶음이 범위를 우회 | `collections`는 표시만, 범위 · 설치 허용은 관리자 설정 |

## 9. 열린 질문(Codex 대조 요청)

1. 연결 전 미리 보기에서 프로필을 받는 경로: 지금 MS4 미리 보기(Setup · Console reader)가 후보 root로 목록 · 등록부를 검증하는 지점에 프로필을 더하는 것이 reader 권한 · 자격 경계를 넘지 않는지.
2. 채널 목록에 `profile` digest를 넣는 것이 MS2 carrier · 하한 · 동결 규칙과 충돌하지 않는지, 프로필만 바뀌어도 목록 판을 올려야 하는지.
3. `package.supplies`를 실행 문서에서 뽑을 때 v1 · v2 · 레거시 번들 모두에서 결정적으로 뽑히는지.
4. 카탈로그 개정을 판정기 · 렌더러 · Setup 봉인 사본에 넣는 가장 작은 구조(개정별 생성본 여러 개 vs 하나에 개정 표지).
5. 설치 후 화면의 개정 거절을 계획(409)에서 하는 것이 MS5b qualified 계획 · fence와 맞는지.
6. 내가 놓친 재평가 대상(이미 구현된 MS6 화면 · 스토어 상세 고정 틀 · S4-3 템플릿 중 바뀌어야 할 것).
