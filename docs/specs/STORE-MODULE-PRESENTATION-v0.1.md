## 1. 원칙

1. **재빌드 0회는 그대로.** 스토어 추가, 스토어 소개 변경, 패키지 소개 변경, 새 패키지 화면은 모두 서명된 데이터다. Backbone 갱신이 필요한 것은 **카탈로그 개정을 올릴 때뿐**이고, 그것도 묶어서 드물게(§5.2). 이 문서를 가능하게 하는 Backbone 변경은 한 번이다.
2. **중립은 지킨다.** 공통 부분에는 **제품을 모르는 표시 정보**만 둔다. OpenSphere 화면은 **별도의 제품 part**에 둔다. 다른 제품은 중립 정보로 자기 화면을 그리고, OpenSphere 화면이 없거나 이 호스트가 못 그리면 OpenSphere도 중립 정보로 그린다(대체 표시).
3. **소개는 주장, 사실은 호스트.** 소개는 **"자기 소개"로 표시한 구역**에만 그린다. 신뢰 · 서명 · digest · 품질 등급 · 권한 · 자원 · 의존 충족 · 설치 상태는 호스트가 계산해 OS 틀로 그린다. 신뢰 상태 행에는 패키지 · 스토어가 정한 글자 · 색을 받지 않는다. 현행 MS6 표현("`minQuality` 미집행", 등급은 "스토어 선언 · 검증 전")을 그대로 쓴다.
4. **보안 상호작용은 OS.** 연결 승인 · 지문 대조 · 범위 · MFA · 설치 승인은 D-97 ③ 그대로. 소개는 초안 · 승인 폼 밖에만 그린다.
5. **서명된 바이트에 묶인다.** 소개 문서는 서명된 목록(또는 번들)이 결합한 **정확한 바이트**로만 출처를 증명한다. 같은 스냅숏으로 활성화되고 롤백 · 동결 규칙을 함께 받는다.
6. **닫힌 데이터, 닫힌 동작.** 소개 화면의 데이터 모델은 호스트가 채운 닫힌 원천만 쓴다(§3). 설치 전 소개에는 Shell 명령 · 설치 동작 · 입력 컨트롤이 없고, 이동은 **호스트가 건넨 대상**으로만 한다(화면이 주소를 만들지 않음). 외부 링크는 OS 링크 구역에서만 연다.
7. **표시 이름은 열쇠가 아니다.** 선택 · 감사 · 원장은 정체(스토어 정체 · 채널 · 스냅숏, 패키지 전체 정체 · 번들)로만 한다.

## 2. 스토어의 자기 소개

### 2.1 스토어 프로필(중립) `store.profile/v1`

| 필드 | 내용 | 한도 |
|---|---|---|
| `storeIdentity` · `rootVersion` · `purpose` | 이 프로필이 속한 스토어 정체 · root 판 · 용도(`store-profile`) | 닫힌 값 |
| `displayName` | 스토어 표시 이름(언어별) | 64자 |
| `summary` | 한 줄 소개(언어별) | 140자 |
| `description` | markdown(호스트 정리 규칙은 계약 §2와 같음) | 16KiB |
| `operator` | 운영 주체 이름 · https 주소 | — |
| `icon` · `banner` | `store.profile-media` 색인의 파일 digest | PNG · WebP만, 각 1MiB, 픽셀 한도 |
| `policies` | 심사 정책 · 보안 공지 · 개인정보 · 이용 조건 링크(https) | 8개 |
| `collections` | 이름 붙인 패키지 묶음: 제목 · 설명 · 전체 패키지 정체 목록 | 묶음 16, 묶음당 64 |
| `locales` | 기본 언어 · 정해진 대체 순서 | 언어 수 · 전체 바이트 상한 |
| `products` | (선택) 제품별 표현 part 참조: 제품 id · 계약 범위 · part digest · size | — |

- **서명과 판:** 새 채널 목록 판이 `profile: { digest, size }`를 담는다. 출처 증명은 위임된 채널 키가 서명한 목록이 결합한 정확한 프로필 바이트다(별도 서명 봉투를 두지 않는다). 목록 v2 · 등록부 v1은 추가 필드를 거절하므로 **각각 새 판**을 열고 옛 판 입력 · digest는 그대로 보존한다.
- **판 번호:** 프로필만 바뀌어도 그 채널 목록의 sequence를 올린다. 등록부가 그대로면 등록부 sequence는 유지한다. 같은 번호 · 다른 바이트는 지금처럼 거절. 프로필 변경은 root 교체나 신뢰 범위 변경을 요구하지 않는다. 대기 중인 MS5b 승인은 같은 항목이 현행 목록에서 여전히 유효하면 진행되고, 계획 스냅숏 · 현행 스냅숏 두 값이 영수증에 남는다.
- **전송(MS2):** 지금 carrier는 `{catalog, registry}`만 받는다. 프로필 · 미디어의 OCI media type · 허용 저장소 · 불변 태그를 OS 계약 원천에서 정하고, 스토어 정체 · 채널 · root · basis와 일치하는 바이트를 검증한 뒤 스냅숏 · 하한 · head를 **한 트랜잭션**에서 올린다. 선언된 프로필이 없거나 digest가 다르면 그 head 승격을 거절한다. 검증된 프로필의 개별 표현 오류는 중립 표시로 대체한다. 실패 동안에도 기존 검증 head의 만료는 계속 계산한다.
- **공급자 소개:** 새 등록부 판의 공급자 항목에 중립 표시 정보(`displayName` · `summary` · https 주소 · 아이콘 digest). "**이 스토어가 표시한 이름**"으로 설명하고, 항상 전체 공급자 정체 · 키 지문 일부를 함께 보인다. 키 관리 승격과 별개다. 공급자 표시 정보가 바뀌면 등록부 sequence와 이를 참조하는 각 채널 목록 sequence를 올린다.
- **`collections`는 소개일 뿐이다.** 범위 · 설치 허용 · 순서는 설치본 관리자 설정이 정한다.

### 2.2 OpenSphere 표현 part `store.profile.opensphere/v1`

- 중립 프로필의 `products`가 가리키는 별도 part. A2UI surface `store.home`(연결 후 스토어 개요의 소개 구역). 연결 전 A2UI(`store.intro`)는 §2.3의 2단계.
- 데이터 원천: §3의 `store.*` · `package.card`만. 없거나 이 호스트가 못 그리면 §2.1 중립 정보로 OS 틀이 그린다.

### 2.3 장면

| 장면 | 보이는 것 |
|---|---|
| **연결 전 미리 보기 — 1단계** | 소유자가 가져온 **크기 제한된 증거 파일**(목록 · 등록부 · 프로필 · 미디어)만 쓴다. 후보 URL은 읽지 않는다. 후보 root로 검증한 **중립 프로필**(이름 · 운영 주체 · 정책 링크 · 소개)을 "자기 소개" 구역에 보인다. OS 구역: "후보 키로 서명 확인 · 설치본에서 승인 대기", 채널 · 유효 기간 · 전체 root 지문, 문서가 주장한 패키지 수와 설치본 범위를 적용한 수(뜻을 구분해 표시). 공급자 · 번들 서명까지 검증한 카드에만 그 사실을 표시. 후보 증거는 **별도 제한된 읽기 응답**으로 투영하고 활성 staging · 하한 · carrier 발급에 연결하지 않는다. 후보 미디어는 메모리의 검증 바이트만 쓰거나 글로 대체. 비공개 후보도 첫 범위는 파일로. 승인은 지금처럼 Setup 소유자 터미널(MS4 · `osr_keyops` · 독립 판정) |
| **연결 전 미리 보기 — 2단계** | 후보 A2UI(`store.intro`)는 §4.1 소개 모드와 브라우저 경계 시험을 통과한 뒤 같은 구역에 더한다. 초안 · 승인 폼 밖, 설치 상태 · Secret · 장치 정보 · 실행 동작은 비움 |
| **연결 후 스토어 개요**(MS6 확장) | OS 틀: 상태, 범위, 공급자, 클래스 · 레이어별 패키지 수, 보안 공지(D-104 L4 뒤). 동기 상태의 **마지막 시도 · 성공 · 검증 · 다음 예정**은 현재 커서 · 최근 실패로 대신할 수 없으므로 **MS2 원장에 각 전이 증거를 더한다**. 소개 구역: `store.home` 또는 중립 프로필. 묶음: 패키지 카드 목록. MS6 관리(root · 범위 · MFA 안내 · 영수증 · 출처 표)는 OS 소유 그대로 |
| **스토어 둘러보기** | 묶음 · 공급자별 패키지 카드, 카드에서 호스트가 건넨 대상의 패키지 소개로 이동 |

시험: 비소유자 403, 후보 URL 무조회, 초안 조회 전후 head · 하한 · 스냅숏 · 영수증 무변경.

## 3. 데이터 원천(설치 전 · 스토어 화면 전용, 새로)

모두 호스트가 검증된 서명 바이트와 원장에서 만든다. 소개 화면이 값을 넣을 수 없다(정적 글자 제외). 조회 권한이 없는 비공개 항목은 이름 · 개수 · 링크도 내지 않는다. Console이 준 원천 값은 승인 입력으로 쓰지 않는다.

| 원천 | 내용 | 계산 위치 |
|---|---|---|
| `store.identity` · `store.profile` | 스토어 정체 · root 지문 일부 · 검증된 프로필 | Services · Console BFF |
| `store.status` · `store.scope` | 동기 상태(전이 증거) · 범위 · 멈춤 | Services |
| `store.publishers` | 등록부의 공급자 표시 정보 · 전체 정체 · 허용 클래스 | Services |
| `store.collections` | 묶음 + 각 항목의 `package.card` | Console BFF |
| `package.card` | 전체 정체 · 표시 이름 · 아이콘 · 요약 · **선택한 스토어 · 채널에서 검증한 제안 판** · 품질(스토어 선언) · 그리고 별도 필드로 활성 설치 판 · 출처 · 이 제안의 적격 여부 · 사유(정지 · 만료 · 미검증 · 회수 · 범위 밖). 설치됨과 범위 밖은 동시에 성립할 수 있다 | Console BFF(Services 출처 · 설치 원장) |
| `package.listing` | 검증된 listing | 선택한 판 · 출처 |
| `package.facts` | 계약 §2의 호스트 계산 사실 | 선택한 판 |
| `package.dependencies` | 의존 패키지의 `package.card` + 판 범위 + 충족 판정(활성 설치본 · 잠금 digest 대조) | Console BFF |
| `package.supplies` | 아래 표 | 선택한 판의 서명 part |
| `package.versions` | 판 기록 | 선택한 출처 |

**`package.supplies` 계산 규칙(결정적인 것만):**

| 증거 | 계산하는 것 |
|---|---|
| 검증된 v2 | 서명된 OpenSphere 제품 part가 지정하고 manifest와 맞는 실행 문서의 Claim 종류 · scheme · 소비 슬롯 |
| 검증된 v1 | 실행 part가 있을 때 같은 원형 규칙. 관계 링크는 정체 매핑이 증명될 때만 |
| 실행 part 없는 레거시 | 서명된 의존 선언만. 공급 · 소비는 "실행 선언 없음"(내장 어댑터 기능을 추정해 넣지 않음) |
| 어셈블리 정의 v1 | 서명된 구성원의 내부 모듈 ID · 역할 · `required` · composition Claim. 정체 매핑 · 잠금이 없으면 이름만 |

- 소비 슬롯의 **필수 여부**는 X2b(D-105)의 서명 계약이 그 뜻을 정한 뒤에 넣는다(지금 `consumes`는 슬롯 하나 · 필수 표지 없음).
- 공급 범위는 실행 문서 · 제품 프로필에서 검증할 수 있는 항목만. 현재 발급 가능성 · 소비자 Secret 이름 · 키는 넣지 않는다. 서명된 선언은 관계를 **설명**하고, 실제 연결은 승인 영수증이 **증명**한다.

## 4. 모듈의 자기 소개

### 4.1 패키지 소개와 소개 모드

- **중립:** `listing` v2 = v1 필드 + 언어별 글 + 스크린샷 대체 글 필수 + `highlights`(짧은 특징 3~6개, 글만).
- **OpenSphere:** 다음 확장 계약 판에 **별도 선택 슬롯 `store.detail.intro`**(A2UI surface 하나)를 둔다. 기존 1.3 screen 배열에 메뉴처럼 끼우지 않고, 공개된 1.3 입력 · 검증 결과는 그대로 보존한다. 스토어 상세 "개요" 탭의 소개 구역에 그린다. 탭 구조와 OS 구역은 그대로다.
- **소개 모드 판정:** 공통 그래프 · 깊이 · 바인딩 검사를 재사용하고, Node · Rust · Setup이 같은 소개 모드로 판정한다. 스키마와 런타임 둘 다 Shell 이벤트 · CommandButton · 호스트 설치 동작 · `command:` · `instance.*` · 폼 입력을 막는다. 소개 surface의 markdown 링크는 비활성화하고, 공개 링크는 OS 링크 구역으로 낸다.
- **이동:** 지금의 같은 섹션 · 활성 메뉴 전용 `navigate`로는 설치 전 패키지 경로를 열 수 없다. 소개 모드의 이동은 **호스트가 그 화면에 건넨 카드의 정확한 대상**을 여는 것뿐이다.
- **판 선택:** 스토어 상세는 **선택한 판 · 출처**, 설치 후 도움말 · 섹션 화면은 **활성 판**. 각각 회귀로 고정한다. 목록의 다른 출처로 조용히 옮기지 않고, 번들이 같아도 선택 출처별 스냅숏 · 회수 상태를 표시한다.
- **적합성 구분:** 새 소개 projection은 이미 검증한 서명 part만 읽고 "형식 · 서명 위반", "필수 화면 개정 미지원", "선택 소개만 미지원"을 구분한다. 선택 소개가 없거나 못 그리면 중립 소개로 간다. 기존 등록 판정의 거절을 중립 표시 성공으로 바꾸지 않는다. 지금 qualified 일반 상세가 레거시 상세의 가시성 검사에 들어가는 경로는 별도 판의 qualified 소개로 선택 출처에 결합하고, 옛 상세 404 · 도움말 계약은 보존한다.

### 4.2 하위 모듈 표기 규칙

- 공급 관계는 §3 규칙으로 **호스트가 뽑는다**. 패키지가 "우리는 X와 함께 쓴다" 같은 관계를 따로 주장하는 필드는 두지 않는다. 추천 조합은 스토어 `collections`의 몫이다.
- 첫 판은 공급 관계를 **접근성 있는 표 · 목록**(기존 List · Text · Icon)으로 그린다. 그래프 전용 컴포넌트는 실제로 필요한 화면과 관계 데이터가 생길 때 더한다.

## 5. A2UI 카탈로그 관리

### 5.1 판 체계

- **카탈로그 id는 주 판:** `opensphere.carbon/v1`. 그 안의 **개정 `1.N`** 은 더하기만 한다. 지우거나 뜻을 바꾸면 `v2`.
- **원천 하나, 개정별 불변 생성본.** 지금 바이트를 1.0으로 고정하고, 생성기와 닫힌 지원 목록에서 개정별 schema · 원천 정책 · digest를 만든다(노드마다 개정 표지를 다는 방식보다 교차 검증 · 폐지 판정이 쉽다). Rust 내장 · Node · Setup 봉인 사본 · 렌더러가 같은 생성본 집합을 쓴다. 저장소에서 임의 schema를 받는 경로는 두지 않는다.
- **화면은 검증 기준 개정 하나를 선언한다:** `catalog: "opensphere.carbon/v1"` + `catalogRevision: "1.1"`(없으면 1.0). 이 값은 "필요한 최소 호스트 개정"이자 "정확히 대조할 고정 스키마"다. 1.0을 선언한 화면이 1.1 컴포넌트를 쓰면 1.1 호스트에서도 거절한다.
- **지원 목록 공개:** `GET /console-api/osr/catalogs`(별도 응답 판, 기존 OsrRead) — 카탈로그 id · 정확한 개정 · digest · 폐지 상태. CLI · SDK도 이 목록을 쓴다.
- **호스트 개정이 낮을 때:**
  - 설치 전 소개 → 중립 소개로 대체, "이 화면은 더 새 OpenSphere가 필요" 한 줄.
  - 설치 후 화면 → **409 `osr_catalog_revision_unsupported`**. 새 설치 · 갱신의 Console 사전 검사와 Core 접수 · 승인 · 실행 직전 검사에서, 계획의 정확한 번들에 서명된 운영 화면 요구 개정을 **독립 계산**한다(번들 digest가 이미 요구 개정을 묶으므로 계획 JSON · fence는 바꾸지 않고, 현재 최고 개정을 fence로 쓰지 않는다).
  - 이미 설치한 판의 정지 · 삭제 · 원래 효과 복구는 기존 승인 근거 그대로.

### 5.2 확장 절차

1. **제안:** 공급자 · 우리 누구나. 그 컴포넌트를 쓸 패키지와 화면 초안이 있어야 받는다(D-97).
2. **정의:** Claude가 계약에 컴포넌트 · 속성 · 바인딩 · 한도 · 금지를 적는다. Carbon 사용 규칙은 컴포넌트 안에 고정.
3. **구현:** Codex가 생성기 · 판정기 둘 · Setup 봉인 사본 · 렌더러 · 공유 사례 · 렌더러 적합성 시험을 한 PR로.
4. **승인 · 반영:** 소유자 승인, 개정 하나 올림. **Backbone 정기 갱신에 묶어 싣는다**(카탈로그 확장 때문에 따로 재빌드하지 않는다).
5. **상류 기본 카탈로그 갱신**도 같은 절차(새 커밋 · sha256 고정, 생성기 `--check`).

### 5.3 폐지

- 컴포넌트 · 속성 폐지는 **예고 → 판정기 경고 → 다음 주 판에서 제거**. 예고 뒤 최소 두 번의 Backbone 정기 갱신 동안 유지.
- 주 판 지원 종료는 그 판을 참조하는 **활성 설치 · 대기 계획 · 롤백 · 복구 증거**가 남아 있으면 하지 않는다(원장으로 확인).

### 5.4 배포

- SDK `@triangles-store/store-sdk`: 개정별 생성 스키마 · 판정기 · 원천 목록 · 공유 사례를 기본으로. 미리 보기는 같은 Console 렌더러를 보호 빌드한 **선택형 정적 앱**(품질 표준, Q-6 범위).
- 스토어 심사(MS7b 게시 도구): 목록 항목의 `targets` 계약 범위와 화면의 카탈로그 개정 대조.
- 외부 공개(카탈로그 단독 배포)는 이번 범위가 아니다(D-97).

### 5.5 소개용 첫 확장 `1.1`

| 컴포넌트 | 내용 | 막는 것 |
|---|---|---|
| **Image** | PNG · WebP만. 선택된 번들 또는 스토어 스냅숏의 색인과 일치하는 파일 digest만, 호스트가 Console origin URL로 바꾼다. 실제 형식 · 픽셀 · 크기 · 전체 바이트 상한 · 대체 글 검증. 현행 Console CSP 그대로 | 외부 URL · data URL · SVG(첫 판) · 다른 번들 미디어 |
| **PackageCard** | 호스트가 만든 닫힌 카드 타입 전체(`package.card`)에만 바인딩. 클릭은 호스트가 발급한 조회 대상만. 상태 · 색 · 등급은 렌더러 고정. 아이콘 → 이름 순서 | 패키지가 카드 내용 · 색을 직접 씀 |

- 첫 판에 넣지 않는 것: LinkList(외부 링크는 OS 링크 구역), FeatureList(기존 List · Icon · Text로), SupplyGraph(§4.2), Video · AudioPlayer · `openUrl` · iframe.
- **미디어 제공 경로:** 지금 listing 미디어는 carrier가 서명 색인과 tar의 digest · 크기를 대조해 적재하고, 상세가 같은 출처의 조회 자격 · 번들 가시성을 대조한 뒤 정확한 경로만 PNG/WebP로 낸다(`private, no-store`, `nosniff`). v2 qualified reader는 OCI blob · 증거만 저장하므로, 새 qualified read projection에서 서명 manifest와 프로필 · 색인을 다시 묶는다. **이미지 URL은 digest만으로 조회되지 않게** 스토어 · 채널 · 스냅숏(또는 전체 패키지 정체 · 번들)에 결합해, 철회 · 정지 정책이 이미지 요청에도 적용된다.

## 6. 위협과 막는 방법

| 위협 | 막는 방법 |
|---|---|
| 소개가 승인 · 신뢰 표시를 흉내 | 소개 구역 띠, 승인 폼 밖, 신뢰 행은 호스트 글자 · 색만, 소개 모드에 입력 · 명령 없음 |
| 다른 스토어 · 공급자 사칭 | "이 스토어가 표시한 이름" + 전체 정체 · 지문 일부, 같은 표시 이름 경고는 보조, 선택 · 감사는 정체로 |
| 서명 없이 소개만 바꿈 | 프로필 digest · size가 목록에, 한 트랜잭션 승격, 같은 번호 다른 바이트 거절 |
| 외부 자원으로 추적 · 변조 | URL 이미지 없음, 미디어는 서명 색인 digest + 출처 결합 URL, CSP 그대로 |
| 철회 뒤에도 미디어 노출 | 이미지 요청에 철회 · 정지 · 만료 정책 적용(시험) |
| 과대 문서 · 미디어 | 계약 §6.3 한도 + 미디어 한도 + 블록 단위 "표시 한도 초과" |
| 연결 전 미리 보기가 상태를 바꿈 · 신뢰를 유도 | 제한된 별도 읽기 응답, head · 하한 · 스냅숏 · 영수증 무변경 시험, "후보 키로 서명 확인 · 승인 대기" OS 표기, 승인은 소유자 터미널 |
| 묶음이 범위를 우회 | `collections`는 표시만 |
| 비공개 항목 노출 | 조회 권한 없으면 이름 · 개수 · 링크도 없음 |

공유 사례에 더할 것: 기존 closed 응답 불변, 같은 digest의 두 출처, 무단 · 만료 · 구 개정 대체, 장문 · 미디어 한도, 악성 소개에서 원장 변경 0건, 기존 북마크 · 탭 · 승인 단추가 소개 모드의 카드 · 동작을 받지 않음.
