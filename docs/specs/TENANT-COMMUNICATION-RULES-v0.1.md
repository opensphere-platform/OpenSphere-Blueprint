## 1. 범위와 현재 공백

이 규칙은 **한 테넌트 안**의 구성요소·어셈블리 사이 통신을 다룬다. 테넌트 경계를 넘는 통신(사원 ↔ 고객)은 교류 계층(X-1)이나 등록된 경계 API만 쓴다. 이 문서는 그 경계 밖 통신을 정하지 않는다.

**공백:**
- 지금 설계의 통신 규칙(D-66, D-69)은 **비동기 이벤트**만 다룬다.
- 실제 결속 통신은 대부분 **각 제품의 고유 프로토콜**이다. 예: Stalwart → PG는 SQL, → AD는 LDAP, → OpenSearch는 HTTP.
- 이 부분에는 규칙이 없다. 이 문서가 그 공백을 메운다.

## 2. 통신 네 종류

| 종류 | 무엇 | 예 | 연결 유형(구성 명세 §6.2) |
|---|---|---|---|
| **결속 통신** | 구성요소가 자기 의존 자원을 쓰는 고유 프로토콜 | Stalwart→PG(SQL), →AD(LDAPS), →OpenSearch(HTTPS) | directory, store, index, blob, trust |
| **서비스 요청** | 다른 어셈블리의 기능을 동기 API로 호출 | 사원 앱 → 메일 API, 에이전트 → 업무 코어 API | api, sso |
| **이벤트** | 일어난 사실의 비동기 통지 | 주문 생성됨, 사용자 비활성화됨 | event |
| **제어 신호** | Governance가 원하는 상태를 앱·엔진에 투영 | 어댑터 → Stalwart 계정 생성 | control |

네 종류는 **경로와 자격을 서로 공유하지 않는다.** 예를 들어 제어 신호를 이벤트 채널로 보내거나, 서비스 요청을 결속 자격으로 하지 않는다.

## 3. 신원

### 3.1 워크로드 신원 (모든 통신에 필수)

```
spiffe://<tenant>.tenant/<assembly>/<component>
예) spiffe://employee.tenant/mail/stalwart
    spiffe://employee.tenant/core-governance/adapter-stalwart
    spiffe://employee.tenant/apps/kim/webmail         # 사원 앱
```

- 테넌트 CA(trust 핵심 어셈블리)가 짧은 수명의 인증서를 발급한다. 기본 24시간 이하, 자동 갱신.
- 모든 연결은 mTLS를 기본으로 한다. 제품이 mTLS를 지원하지 않으면 TLS + 연결 전용 자격으로 보완하고, 예외 목록에 올린다.

### 3.2 사용자 위임 토큰 (사람 대신 하는 서비스 요청에 필수)

- 형식: OAuth 2.0 토큰 교환(RFC 8693)으로 받은 짧은 수명 토큰. 기본 5분 이하.
- 필수 클레임:

| 클레임 | 의미 |
|---|---|
| `sub` | 원래 사용자(사원) |
| `act` | 행위자 사슬. 에이전트·앱의 워크로드 신원을 중첩해 기록한다. 최대 깊이 2(D-47) |
| `aud` | 호출 대상 어셈블리. 다른 어셈블리에 재사용할 수 없다 |
| `scope` | 요청 범위. **할당 ∩ 위임자 현재 권한 ∩ 자율 상한**(D-46) |
| `tenant` | 테넌트 ID. 다르면 거부한다 |

- 받는 쪽은 워크로드 신원과 위임 토큰을 **둘 다** 검증한다. 둘 중 하나라도 실패하면 거부한다.

## 4. 결속 통신 규칙

| ID | 규칙 |
|---|---|
| **TC-B1** | 연결 그래프에 있는 연결만 통신할 수 있다. 네트워크 정책은 그래프에서 자동 생성하고 손으로 고치지 않는다 |
| **TC-B2** | 연결마다 전용 자격을 쓴다. 자격은 연결 객체가 발급·회전한다 |
| **TC-B3** | 권한은 연결 선언의 `access`(read / write / owner)를 넘지 않는다 |
| **TC-B4** | **DB는 주인 구성요소만 연다.** 다른 어셈블리는 그 DB에 직접 붙지 않고 서비스 요청이나 이벤트를 쓴다(B-4를 테넌트 안으로 가져온 규칙) |
| **TC-B5** | 공유 관리자 계정(PG `postgres`, AD Domain Admin, OpenSearch `admin`)은 결속에 쓰지 않는다. 이 계정은 봉인하고, 비상 경로에서만 연다 |

**프로토콜별 최소 요건**

| 프로토콜 | 요건 |
|---|---|
| LDAP | LDAPS 또는 StartTLS 필수, 단순 바인드는 연결 전용 읽기 계정만, 익명 바인드 금지 |
| PostgreSQL | TLS 필수, SCRAM 또는 클라이언트 인증서, 연결 전용 역할, `pg_hba`는 그래프에서 생성 |
| OpenSearch | TLS 필수, 역할 매핑은 연결 단위, 색인 범위 제한 |
| S3 호환 | 버킷 범위 키, 서버 측 암호화 키는 테넌트 KMS |
| SMTP(내부 중계) | 내부 구간도 TLS, 중계 허용은 그래프 기준 |

## 5. 서비스 요청 규칙

| ID | 규칙 |
|---|---|
| **TC-R1** | **등록된 API 계약만** 호출할 수 있다. 계약은 OpenAPI 또는 gRPC 정의로 레지스트리에 등록하고 버전을 붙인다 |
| **TC-R2** | 모든 호출에 워크로드 신원이 필요하고, 사람 대신 하는 호출이면 위임 토큰도 필요하다(§3) |
| **TC-R3** | 권한 판단은 받는 쪽이 PDP에 질의해서 한다. 질의 형식은 AuthZEN 형태(주체·행위·자원·맥락)로 통일한다. 보내는 쪽 판단을 믿지 않는다 |
| **TC-R4** | 상태를 바꾸는 호출에는 멱등 키가 필요하다. 받는 쪽은 같은 키를 24시간 이상 기억한다 |
| **TC-R5** | 기본 제한 시간은 5초다. 재시도는 멱등 호출에만, 지수 백오프로 최대 3회 한다 |
| **TC-R6** | 오류는 공통 형식(RFC 9457 Problem Details)으로 돌려준다. 권한 거부는 이유 코드를 포함하되, 내부 정책 내용은 노출하지 않는다 |
| **TC-R7** | 계약 변경은 하위 호환을 원칙으로 한다. 호환이 깨지면 새 메이저 버전으로 병행 운영하고, 이전 버전의 종료일을 공지한다 |

## 6. 이벤트 규칙

D-69의 계약 규칙 6개(CloudEvents, 스키마 등록, outbox, 멱등, 위임 토큰, 키 순서)를 테넌트 채널에 그대로 적용하고, 아래를 더한다.

| ID | 규칙 |
|---|---|
| **TC-E1** | 테넌트마다 채널 하나(D-66). 어셈블리마다 채널을 따로 만들지 않는다. Odoo 자체 큐·웹훅 같은 제품 내장 경로는 내부용으로만 쓰고, 테넌트 밖으로 알릴 때는 outbox → 채널로만 낸다 |
| **TC-E2** | **이벤트는 사실 통지다.** 다른 어셈블리에 일을 시키는 명령은 서비스 요청으로 한다 |
| **TC-E3** | 필수 속성: `id`, `source`(워크로드 신원), `type`, `subject`, `time`, `tenant`, `partitionkey`, `traceparent`, `actor`(사람 대신이면 사용자 ID) |
| **TC-E4** | 개인정보는 본문에 싣지 않는다. 식별자만 싣고, 받는 쪽이 권한을 가지고 다시 조회한다(claim check) |
| **TC-E5** | 주제(type)별로 발행 권한과 구독 권한을 연결 객체에 선언한다. 선언 없는 구독은 거부한다 |
| **TC-E6** | 처리 실패는 재시도 후 격리 큐(DLQ)로 보낸다. 격리 큐는 운영 경보 대상이다 |
| **TC-E7** | 보존 기간은 주제별로 정한다. 기본 7일, 감사 관련 주제는 감사 보존 기준을 따른다 |

## 7. 제어 신호 규칙

| ID | 규칙 |
|---|---|
| **TC-C1** | Governance → 어댑터 → 앱·엔진의 경로만 쓴다. 계약은 SCIM 형태(create / update / disable / delete / list, 기준선 §6) |
| **TC-C2** | 어댑터는 앱마다 하나, 어댑터 자격은 그 앱의 관리 API 범위로 제한한다 |
| **TC-C3** | 제어 신호는 업무 채널을 쓰지 않는다. 업무 채널이 막혀도 회수(D-21)는 동작해야 한다 |
| **TC-C4** | 앱 관리 화면에서 직접 바꾼 권한은 대조(list)에서 발견해 초과 권한으로 회수한다(레드팀 R-11 권고) |

## 8. 관측과 감사

- 모든 통신은 W3C `traceparent`를 전파한다.
- 감사 기록 필수 필드: 시각, 테넌트, 보낸 워크로드 신원, 행위자 사슬, 대상, 행위, 결과, 판단 근거 ID(PDP 결정 ID).
- 감사 기록은 테넌트 안에 남기고, 해시 사슬을 테넌트 키로 서명한다. Backbone에는 지표만 간다(B-3).

## 9. 금지 목록

- 연결 그래프에 없는 통신
- 다른 어셈블리 DB에 직접 접속
- 공유 관리자 계정으로 하는 결속
- 워크로드 신원 없는 호출, 또는 토큰만 믿는 호출
- 이벤트로 명령 보내기
- 이벤트 본문에 개인정보 싣기
- 제어 신호를 업무 채널로 보내기
- 테넌트 경계를 직접 넘는 통신(교류 계층 우회)
- `/internal/*`처럼 "내부라서 안전하다"는 가정에 기댄 무인증 경로
